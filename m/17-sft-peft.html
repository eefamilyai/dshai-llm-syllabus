Supervised Fine-Tuning and Parameter-Efficient Tuning

Turning a next-token predictor into an assistant, and doing it on one GPU.

on this page

Why this module exists

A pretrained model is a very good model of text and a very bad assistant. It will continue your question rather than answer it, because continuing is what it was trained to do. Supervised fine-tuning is the smallest, cheapest, most misunderstood stage of the pipeline: a few thousand examples and a few GPU-hours convert a document completer into something that follows instructions, and almost nobody can say precisely why so little data works or which tokens the gradient actually touches. Then LoRA and QLoRA make that stage affordable on a single accelerator, by a low-rank argument that is worth deriving rather than memorising. If you skip this module you will fine-tune on the wrong tokens, evaluate with the wrong metric, mistake formatting for capability, and believe that a 0.5% parameter budget is a heuristic when it is a consequence of the update's spectrum.

The fine-tuning loss is always written over response tokens; $m_t$ is the mask that enforces it.

Core concepts

Why a pretrained model is not an assistant

(1) Intuition. Ask a document completer "What is the capital of France?" and the most likely continuation, given a corpus full of question lists, is another question. The model is doing exactly what it was trained to do; the task you wanted was never in the objective.

(2) Formal definition. Pretraining minimizes $-\mathbb{E}_{x\sim p_{\text{data}}}\log p_\theta(x)$. The distribution $p_{\text{data}}$ is the web, and the web contains questions, forum threads, exam papers, and dialogue — but its dominant conditional structure is "text continues text". Instruction following is a conditional $p(\text{response}\mid\text{instruction})$ with a much narrower, non-representative support.

(3) Why it is built this way. Nothing is broken; the base model is a general-purpose conditional distribution and SFT is a change of which conditional you sample from, enforced by a tiny amount of data that reweights the distribution toward the assistant-like subset. This is why SFT needs so few examples: it is not teaching knowledge, it is selecting a mode that already exists.

(4) Worked micro-example. Base model, prompt Q: What is 2+2?\nA:. The continuation 2+2=4. has high probability (a fact); so does What is 2+3? (a question list). After SFT on 5,000 (instruction, response) pairs, the second mode's probability collapses because every training document in the new distribution ends after one answer. The knowledge did not change; the conditional did.

Instruction data: human, distilled, and how much

(1) Intuition. You need examples of an assistant behaving well. You can pay people to write them, or you can take them from a stronger model. The second is cheaper by orders of magnitude and is now standard, which makes SFT partly a distillation procedure whether or not it says so.

(2) Formal definition. A human-written dataset is triples $(x, y, \text{annotator})$ with quality control through guidelines and inter-annotator agreement. A distilled dataset is $y\sim \pi_{\text{strong}}(\cdot\mid x)$ for prompts $x$ drawn from a distribution you control. The LIMA result is that about 1,000 carefully curated examples, with no RLHF, produce a usable assistant — evidence that SFT is mode selection rather than knowledge injection.

(3) Why it is built this way. Quality dominates quantity because the model is being taught a format and a policy, not facts. A thousand examples that are all correct, diverse, and stylistically consistent teach the mode cleanly; a million that are inconsistent teach an average of several incompatible modes. The usual failure of large distilled datasets is homogeneity: generated from one teacher with one style, they narrow the model.

(4) Worked micro-example. 1,000 examples at 400 tokens each is 400,000 tokens — 0.03% of a 1.4T-token pretraining run. The compute is a rounding error on pretraining. But 1,000 examples is also small enough that a single duplicated example shifts the loss measurably, which is why deduplication and decontamination matter more here than at any other stage.

Loss masking, and which tokens get gradient

(1) Intuition. A chat example is a prompt followed by a response. You want the model to learn to produce the response, not to produce the prompt. So you compute the loss only on response tokens.

(2) Formal definition. With mask $m_t\in\{0,1\}$,

$$\mathcal{L} = -\frac{1}{\sum_t m_t}\sum_{t=1}^{N} m_t \log p_\theta(x_t\mid x_{

Masked positions contribute exactly zero to the loss and therefore exactly zero to the gradient.

(3) Why it is built this way. The target is $p(\text{response}\mid\text{prompt})$, and its log is $\log p(q,r) - \log p(q)$, which involves two terms. Maximizing $\log p(q,r)$ over $\theta$ increases both terms, including $p(q)$ — so unmasked training literally teaches the model to generate plausible user turns, and weights each example by its prompt length. Masking removes the $\log p(q)$ contamination. The normalization choice matters too: dividing by $\sum_t m_t$ makes each example contribute equally regardless of response length, while dividing by $N$ silently down-weights short responses and, with a long shared system prompt, makes the loss look excellent while barely training anything.

(4) Worked micro-example. A 512-token example with a 400-token prompt and a 112-token response. Masked, the loss averages 112 terms and the gradient is that of a 112-token objective. Unmasked, it averages 512 terms and 78% of the gradient is devoted to making the model better at writing prompts. If the average prompt is 4x the average response, you are spending 80% of the budget on the wrong task.

Chat templates and format consistency

(1) Intuition. The model must know where the user's turn ends and its own begins. That is encoded by special tokens in a fixed template, and the template is part of the model.

(2) Formal definition. A template is a function from a list of (role, content) pairs to a token sequence, using reserved special tokens: system preamble, then <|user|> content <|assistant|> content <|end|>, repeated. Training and inference must use byte-identical templates, including the exact spaces, the exact special token ids, and the same treatment of a trailing newline.

(3) Why it is built this way. The model learns the transition "after <|assistant|>, generate until <|end|>" purely from data. If inference uses a different template, that transition was never trained, and the model either fails to stop or emits the wrong role's text. Three failure modes follow: (i) the model continues past its turn because the end token distribution is off-template; (ii) it generates the user's next message because the template resembles a two-party continuation; (iii) your evaluation measures a distribution the model never saw, so scores are meaningless even when the outputs look fine.

(4) Worked micro-example. Two templates that differ by one space: <|user|> hi versus <|user|>\nhi. If the tokenizer does not merge the newline into the preceding token, these produce different token ids at the boundary, and the model conditions on a prefix it has never seen. The symptom is subtle — a mild degradation, occasional role confusion — and it is the first thing to check when a fine-tune underperforms.

Catastrophic forgetting and the alignment tax

(1) Intuition. Fine-tuning on narrow data moves the weights toward that data, and the model forgets things it used to do. The gap between the original and the fine-tuned model's general capability is the alignment tax.

(2) Formal definition. After SFT the model optimizes $\mathbb{E}_{(q,r)\sim\mathcal{D}_{\text{SFT}}}[-\log p_\theta(r\mid q)]$. The old objective's optimum is no longer stationary, so the loss on general data $\mathbb{E}_{x\sim p_{\text{data}}}[-\log p_\theta(x)]$ rises. The tax is the difference in downstream benchmark scores between the base and tuned model, holding evaluation fixed.

(3) Why it is built this way. The tax is a consequence of the objective change, not a bug, and it is why SFT is done at a small learning rate for few epochs, why parameter-efficient methods reduce it (fewer degrees of freedom to move), and why replay data from pretraining is mixed in. Note the direction: a model tuned on 1,000 examples for 3 epochs shows almost no tax; tuned on 100,000 for 10 epochs, the tax is measurable and sometimes large.

(4) Worked micro-example. Base model scores 72.0 on a reasoning benchmark. After SFT on a formatting-heavy dataset for 5 epochs, it scores 74.5 on the target format benchmark and 66.8 on reasoning — a 5.2-point tax for a 2.5-point target gain. Reducing to 1 epoch and mixing 10% pretraining data recovers reasoning to 70.9 while keeping the format gain at 2.9 points. This is the trade you are actually making, and it is measurable in an afternoon.

Full fine-tuning cost

(1) Intuition. Fine-tuning a model means holding everything you need to update it. For a 7B model that is not 14 GB of weights; it is over 100 GB.

(2) Formal definition. Per parameter, mixed-precision AdamW needs 2 bytes for the bf16 weight used in the forward pass, 2 for the bf16 gradient, 4 for the fp32 master weight, and 8 for the two fp32 moments: 16 bytes per parameter. Activations add a term proportional to batch size times sequence length times width times depth, and may be reduced by gradient checkpointing at the cost of an extra forward pass.

(3) Why it is built this way. The fp32 master weight exists because bf16 updates below one part in 256 round to nothing (see M16). The moments exist because Adam needs a first and second moment. Neither is optional, and together they are 75% of the memory.

(4) Worked micro-example. A 6.74B-parameter model (32 layers, $d=4096$, $d_{ff}=11008$, $V=32000$) needs $6.74\times10^{9}\times16 = 107.8$ GB, or 100.4 GiB, before a single activation. On 80 GB devices that is at least two, realistically four with activations and fragmentation — and that is for 7B. LoRA is not a convenience; for anything above 13B it is the difference between running and not running.

LoRA: the low-rank update

(1) Intuition. The change that fine-tuning makes to a weight matrix is not full-rank. If a rank-8 approximation captures most of it, you can store 8 rows and 8 columns instead of a whole matrix.

(2) Formal definition. Freeze $\mathbf{W}_0$ and add a low-rank branch:

$$\mathbf{h} = \mathbf{W}_0\mathbf{x} + \frac{\alpha}{r}\mathbf{B}\mathbf{A}\mathbf{x}, \qquad \mathbf{A}\in\mathbb{R}^{r\times d_{\mathrm{in}}},\ \ \mathbf{B}\in\mathbb{R}^{d_{\mathrm{out}}\times r}$$

with $\mathbf{B}$ initialized to zero and $\mathbf{A}$ initialized at random. Trainable parameters per adapted matrix: $r(d_{\mathrm{in}}+d_{\mathrm{out}})$ instead of $d_{\mathrm{in}}d_{\mathrm{out}}$.

(3) Why it is built this way. $\mathbf{B}=\mathbf{0}$ makes the branch exactly zero at initialization, so the model starts from the pretrained function with no degradation, and — see Derivation 2 — the first gradient with respect to $\mathbf{A}$ is zero, so the two factors never collapse together. Adapting attention projections is the default because they carry the largest task-specific signal per parameter; adding the MLP projections roughly doubles the parameter count and helps on harder tasks.

(4) Worked micro-example. For $d=4096$, $r=16$: $16(4096+4096) = 131{,}072$ parameters instead of $16{,}777{,}216$ — 0.78%. For the full 6.74B model with $r=16$ on all seven linear projections of every layer: 39.98M trainable, 0.59% of the base.

QLoRA: quantize the frozen part

(1) Intuition. The base weights do not move, so they do not need to be precise. Store them in 4 bits, keep the adapters in bf16, and dequantize on the fly for each matmul.

(2) Formal definition. Three ingredients. NF4: blockwise 4-bit quantization where the 16 levels are the quantiles of a normal distribution rather than a uniform grid. Double quantization: the per-block scaling constants are themselves quantized, from fp32 to 8 bits with their own per-256-block scale. Paged optimizers: optimizer state is kept in pageable host memory so a transient memory spike pages out instead of crashing.

(3) Why it is built this way. Blockwise absmax scaling normalizes each block of 64 weights to $[-1,1]$, so one outlier cannot ruin the precision of its neighbours. Quantile levels put more resolution where a Gaussian's mass actually is. Double quantization removes most of the 0.5 bits per parameter that the scaling constants would otherwise cost. The result is a frozen base at 4.127 bits per parameter with the adapters still in bf16, so gradient quality is unharmed.

(4) Worked micro-example. A 6.74B model at 4.127 bits is $6.74\times10^{9}\cdot4.127/8 = 3.48$ GB (3.36 GiB), against 13.04 GiB in bf16. Plus 40M adapter parameters at 16 bytes each (0.64 GB) and activations, which fits comfortably in 24 GB.

DoRA and the rest of the PEFT family

(1) Intuition. LoRA changes magnitude and direction in one entangled update. DoRA splits the weight into a magnitude vector and a direction matrix, and adapts the direction with LoRA while training the magnitude separately.

(2) Formal definition. DoRA computes

$$\mathbf{W}' = \mathbf{m}\frac{\mathbf{W}_0 + \mathbf{B}\mathbf{A}}{\|\mathbf{W}_0+\mathbf{B}\mathbf{A}\|_c}$$

where $\mathbf{m}\in\mathbb{R}^{d_{\mathrm{out}}}$ is a trainable magnitude vector, initialized to $\|\mathbf{W}_0\|_c$, and the norm is taken column-wise. Trainable parameters: LoRA's $r(d_{\mathrm{in}}+d_{\mathrm{out}})$ plus $d_{\mathrm{out}}$.

(3) Why it is built this way. Analysis of full fine-tuning shows its updates tend to change direction and magnitude somewhat independently, which LoRA's single rank-$r$ term cannot reproduce; DoRA gives magnitude its own degrees of freedom at a cost of $d_{\mathrm{out}}$ parameters — for $d=4096$, 4,096 parameters per adapted matrix, negligible. Prefix and prompt tuning go further: they add no matrix at all, prepending $k$ learned vectors to the keys and values (prefix) or to the input embeddings (prompt). They are cheaper still and generally weaker for knowledge-heavy tasks; adapters (small bottleneck MLPs inserted between blocks) sit in between and add inference latency unless merged.

(4) Worked micro-example. $r=16$, $d_{\text{in}}=d_{\text{out}}=4096$: LoRA has 131,072 parameters, DoRA has 135,168 (+3.1%), prefix tuning with $k=20$ has $20\cdot2\cdot l\cdot d$ key-value entries in the attention operations, which for $l=32$ is 5.2M — more than LoRA, and not mergeable into the weights. The intuition that "prefix tuning is the cheapest" is often wrong once you account for the number of layers you must touch.

Did the fine-tune actually work?

(1) Intuition. Training loss going to zero on 1,000 examples means the model memorized 1,000 examples. It says nothing about whether it learned the behaviour.

(2) Formal definition. Four measurements, all necessary: (i) held-out target performance on examples from the same distribution but not trained on; (ii) format adherence — does it always emit the required structure, measured on a large sample including adversarial inputs; (iii) capability retention — the pretraining-era benchmarks, run identically before and after; (iv) overfitting diagnostics — training loss versus held-out loss per epoch, and the epoch at which they diverge, typically 1–3 for small sets.

(3) Why it is built this way. A fine-tune can succeed on (i) and fail (ii), which means you taught a style rather than a behaviour, or succeed on both and fail (iii), which means the alignment tax ate the model. Reporting only the target metric is how a broken fine-tune ships.

(4) Worked micro-example. 1,000 examples, 3 epochs, batch 8: 375 steps. Training loss 1.9 → 0.4. Held-out loss 1.7 → 1.4 → 1.6 over the three epochs — the minimum is at epoch 1 and you have already overfit by epoch 3. Format adherence measured on 500 unseen prompts: 96% on in-distribution, 61% on prompts with an unusual capitalisation. Capability retention: −0.8 points. The correct deployable checkpoint is epoch 1, and only the four-measurement protocol reveals it.

The algorithm, step by step

  1. Prepare data. Assemble (instruction, response) pairs; deduplicate; decontaminate against your evaluation sets; strip any formatting that leaks answers.
  2. Apply the template. Render each pair through the exact chat template the deployed model will use, including special tokens.
  3. Tokenize and build the mask. Set $m_t=1$ for response tokens (including the end-of-turn token, so the model learns to stop) and $m_t=0$ for the template and prompt.
  4. Pack or pad. Pack multiple examples into a fixed sequence length with correct mask realignment, or pad with a token that is masked out. Packing without resetting the attention mask across examples lets them attend to each other.
  5. Attach adapters. Wrap the chosen linear modules with a LoRA branch, leaving everything else frozen; verify that the trainable parameter count is what you intended.
  6. Train. AdamW at a learning rate one to two orders below pretraining, 1–3 epochs, with the masked loss and gradient clipping.
  7. Merge or keep separate. For LoRA, $\mathbf{W}_0 + \frac{\alpha}{r}\mathbf{B}\mathbf{A}$ can be folded into the base weight at inference with zero latency cost; for prefix tuning it cannot.
  8. Evaluate. Held-out target, format adherence, capability retention, overfitting curve.

```text function SFT_STEP(batch, model, template, adapter): total_loss, total_masked <- 0, 0 for (instruction, response) in batch: ids <- tokenize(template(instruction, response)) prompt_len <- len(tokenize(template(instruction, ""))) # template boundary mask <- [0] * prompt_len + [1] * (len(ids) - prompt_len) logits <- model.forward(ids) # (len(ids), V) logp <- log_softmax(logits[:-1]) # predict ids[t+1] from t target <- ids[1:] mask_t <- mask[1:] total_loss += -(logp[arange, target] * mask_t).sum() total_masked += mask_t.sum() loss <- total_loss / total_masked (loss).backward() # grads only reach the adapters clip_grad_norm(model.trainable_parameters(), 1.0) optimizer.step(); optimizer.zero_grad() return loss ```

Complexity. Training FLOPs $= 6 P_{\text{body}} N_{\text{tokens}}$ for the forward and backward pass — LoRA does not reduce the compute, only the memory and the number of trainable parameters, which is the most common misunderstanding about it. Backward through the frozen weights is skipped only when the input activations to those modules do not need gradients, which is true for the first adapted layer and false for deeper ones, so in practice the FLOP saving is small. Memory is where the win is: $16 P_{\text{trainable}}$ bytes for optimizer state instead of $16P$.

Derivations

Derivation 1: the masked loss is the conditional likelihood

Step 1 — what the two objectives are. Unmasked, $\mathcal{L}_{\text{joint}} = -\frac{1}{N}\sum_t\log p_\theta(x_t\mid x_{

Step 2 — the gradient. Both are sums of terms, so

$$\frac{\partial\mathcal{L}_{\text{cond}}}{\partial\theta} = -\frac{1}{M}\sum_t m_t\frac{\partial\log p_\theta(x_t\mid x_{

For any $t$ with $m_t=0$ the term is multiplied by zero. Masked positions receive no gradient: not small, not attenuated — zero.

Step 3 — why the unmasked objective is the wrong one. Factor the joint as $p(q,r) = p(q)\,p(r\mid q)$, so $\log p(q,r) = \log p(q) + \log p(r\mid q)$. Then

$$\nabla_\theta \log p(q,r) = \nabla_\theta\log p(q) + \nabla_\theta\log p(r\mid q)$$

The first term is not zero. Unmasked training therefore takes a gradient step that increases the likelihood of the prompt as well — that is, it makes the model better at writing prompts. Since prompts are typically much longer than responses in templated data (a system preamble alone can be hundreds of tokens), this term can dominate.

Step 4 — the normalization. Dividing by $M$ rather than $N$ makes the per-example weight independent of length. Dividing by $N$ gives each token equal weight, which is defensible in principle and wrong in practice for chat data: with a 400-token system prompt shared by every example and a 50-token answer, the loss is 89% identical across examples and the gradient signal from the answer is diluted 8x.

Derivation 2: LoRA gradients, the zero init, and the $\alpha/r$ scaling

Step 1 — set up. Let $\mathbf{h} = \mathbf{W}_0\mathbf{x} + s\mathbf{B}\mathbf{A}\mathbf{x}$ with $s = \alpha/r$, and let $\mathbf{g} = \partial\mathcal{L}/\partial\mathbf{h}\in\mathbb{R}^{d_{\mathrm{out}}}$ be the upstream gradient, which is unchanged whether or not an adapter is present.

Step 2 — gradient with respect to $\mathbf{B}$. Write the branch output's $i$-th component as $s\sum_k B_{ik}(\mathbf{A}\mathbf{x})_k$. Then $\partial h_i/\partial B_{ik} = s(\mathbf{A}\mathbf{x})_k$, so

$$\frac{\partial\mathcal{L}}{\partial B_{ik}} = s\,g_i(\mathbf{A}\mathbf{x})_k \implies \frac{\partial\mathcal{L}}{\partial\mathbf{B}} = s\,\mathbf{g}(\mathbf{A}\mathbf{x})^{\top}$$

Step 3 — gradient with respect to $\mathbf{A}$. Now $h_i = s\sum_k B_{ik}\sum_j A_{kj}x_j$, so $\partial h_i/\partial A_{kj} = s B_{ik}x_j$, giving

$$\frac{\partial\mathcal{L}}{\partial A_{kj}} = s\sum_i g_i B_{ik}x_j = s(\mathbf{B}^{\top}\mathbf{g})_k x_j \implies \frac{\partial\mathcal{L}}{\partial\mathbf{A}} = s\,\mathbf{B}^{\top}\mathbf{g}\,\mathbf{x}^{\top}$$

Step 4 — the zero initialization. At $\mathbf{B}=\mathbf{0}$, Step 3 gives $\partial\mathcal{L}/\partial\mathbf{A} = \mathbf{0}$ exactly: on the first step only $\mathbf{B}$ moves. The two factors therefore cannot both collapse toward zero, which is what would happen if both were initialized small and symmetric. Numerically, with $\mathbf{B}=\mathbf{0}$ the analytic $\partial\mathcal{L}/\partial\mathbf{A}$ is a matrix of exact zeros and matches a finite-difference estimate to $10^{-10}$ — a good gradient check that also confirms the zero is structural, not numerical.

Step 5 — the first step's effect on the output. One gradient step gives $\Delta\mathbf{B} = -\eta s\,\mathbf{g}(\mathbf{A}\mathbf{x})^{\top}$, so the change in the branch output is

$$\Delta\mathbf{h} = s\,\Delta\mathbf{B}(\mathbf{A}\mathbf{x}) = -\eta s^{2}\,\|\mathbf{A}\mathbf{x}\|^{2}\,\mathbf{g}$$

Step 6 — what $\alpha$ actually controls. Substituting the same initialization result, $\mathbb{E}\|\mathbf{A}\mathbf{x}\|^{2} = r\|\mathbf{x}\|^{2}/(3d_{\mathrm{in}})$, into Step 5 gives

$$\Delta\mathbf{h} = -\eta\left(\frac{\alpha}{r}\right)^{2}\frac{r\|\mathbf{x}\|^{2}}{3d_{\mathrm{in}}}\,\mathbf{g} = -\frac{\eta\alpha^{2}}{r}\cdot\frac{\|\mathbf{x}\|^{2}}{3d_{\mathrm{in}}}\,\mathbf{g}$$

So the first step's effect on the output scales as $\alpha^{2}/r$: $\alpha$ and $r$ do not act independently. Halving $\alpha$ quarters the initial step, doubling $r$ halves it. This is the sense in which $\alpha/r$ is one hyperparameter wearing two names.

Step 7 — the invariance that $\alpha = r$ actually buys. The loss depends on $\mathbf{A}$ and $\mathbf{B}$ only through the product $\mathbf{B}\mathbf{A}$, so the reparameterization $\mathbf{B}\to (r/\alpha)\mathbf{B}'$ leaves every forward pass identical. Apply it to the weight-decay penalty, which acts on $\mathbf{B}$:

$$\lambda\|\mathbf{B}\|_F^{2} = \lambda\left(\frac{r}{\alpha}\right)^{2}\|\mathbf{B}'\|_F^{2}$$

The effective regularization strength in output space is therefore $\lambda(r/\alpha)^{2}$, which is not rank-invariant unless $\alpha\propto r$. Setting $\alpha = r$ makes the effective $\lambda$ the same for $r=8$ and $r=256$, which is exactly what you want when sweeping rank at a fixed weight-decay setting. That is the defensible justification for the convention — and note its limits: it fixes the regularization balance, not the first-step magnitude, which still scales as $1/r$. If you move between $r=8$ and $r=128$, expect to revisit the learning rate even at $\alpha = r$. Two further consequences follow from the same algebra: at $\alpha=r$ the scale factor is exactly 1, so "LoRA with $\alpha=r$" and "LoRA with no scaling" are the same model; and the $1/(3d_{\mathrm{in}})$ in Step 6 means the effective step changes when you adapt a module of different width, which is why aggressive setups sometimes use per-module learning rates.

Derivation 3: Eckart–Young, and what "low-rank" costs

Step 1 — the best rank-$r$ approximation. Let $\mathbf{M} = \mathbf{U}\mathbf{\Sigma}\mathbf{V}^{\top} = \sum_i\sigma_i\mathbf{u}_i\mathbf{v}_i^{\top}$. For any rank-$r$ matrix $\mathbf{X}$,

$$\|\mathbf{M}-\mathbf{X}\|_F^{2} = \|\mathbf{M}\|_F^{2} - 2\langle\mathbf{M},\mathbf{X}\rangle_F + \|\mathbf{X}\|_F^{2}$$

Step 2 — bound the inner product. By von Neumann's trace inequality, $\langle\mathbf{M},\mathbf{X}\rangle_F = \operatorname{tr}(\mathbf{M}^{\top}\mathbf{X}) \le \sum_{i=1}^{r}\sigma_i\mu_i$ where $\mu_1\ge\cdots\ge\mu_r$ are $\mathbf{X}$'s singular values, and $\sum_i\sigma_i\mu_i \le \sum_{i=1}^{r}\sigma_i\|\mathbf{X}\|_F$ with equality when the top singular vectors align.

Step 3 — the minimum. For $\mathbf{X} = \mathbf{M}_r = \sum_{i\le r}\sigma_i\mathbf{u}_i\mathbf{v}_i^{\top}$ we get $\|\mathbf{M}-\mathbf{M}_r\|_F = \sqrt{\sum_{i>r}\sigma_i^{2}}$, and no rank-$r$ matrix does better. So

$$\min_{\operatorname{rank}(\mathbf{X})\le r}\|\mathbf{M}-\mathbf{X}\|_F = \sqrt{\sum_{i>r}\sigma_i^{2}}$$

Step 4 — connecting to LoRA. LoRA parameterizes $\mathbf{B}\mathbf{A}$, which is exactly a rank-$r$ matrix, so it can represent the best rank-$r$ approximation and nothing better. The approximation error is the tail of the spectrum. The low-rank hypothesis is the empirical claim that the spectrum of $\Delta\mathbf{W}$ from fine-tuning decays fast, so this tail is small at small $r$. Two caveats worth stating: LoRA is initialized at $\mathbf{B}=\mathbf{0}$ so it starts at rank 0 and grows; and the hypothesis is about the update, not the pretrained weight, whose spectrum does not decay as fast. Reports of the intrinsic dimensionality of fine-tuning being in the hundreds support the hypothesis for narrow tasks and less so for broad ones, which is why rank choice is task-dependent (8–16 for style, 64–256 for new capabilities).

Derivation 4: the QLoRA bit budget and the quantization error

Step 1 — blockwise 4-bit. With one fp32 absmax constant per block of 64 weights, the cost per parameter is

$$4 + \frac{32}{64} = 4 + 0.5 = 4.5\ \text{bits}$$

Step 2 — double quantization. Quantize the absmax constants themselves to 8 bits, grouped 256 at a time, with one fp32 scale per group of 256 constants:

$$\text{overhead} = \frac{1}{64}\left(8 + \frac{32}{256}\right) = \frac{1}{64}(8 + 0.125) = 0.1270\ \text{bits}$$

Step 3 — total.

$$b = 4 + 0.1270 = 4.127\ \text{bits per parameter}$$

which is the published figure, and saves 0.373 bits against naive blockwise quantization — 8.3% of the storage, for a 6.74B model a saving of 0.31 GB. Small, but free.

Step 4 — where the 16 levels should go. A quantizer with level spacing $\Delta(x)$ has mean squared error, to leading order in the high-rate limit,

$$\text{MSE} \approx \frac{1}{12}\int \Delta(x)^{2}p(x)\,dx = \frac{1}{12}\int\frac{p(x)}{\lambda(x)^{2}}dx$$

with level density $\lambda = 1/\Delta$. Minimizing subject to $\int\lambda\,dx = 2^{b}$ via a Lagrange multiplier: $-2p/\lambda^{3}+\mu = 0$, so $\lambda\propto p^{1/3}$ and $\Delta\propto p^{-1/3}$ — levels are denser where the density is high, specifically as the cube root.

Step 5 — why NF4 uses quantiles. The MSE-optimal spacing is $p^{-1/3}$, not the equal-probability spacing $1/p$ that quantile levels give. Quantile levels are therefore not exactly optimal, but they are close for a Gaussian and much better than uniform:

bits uniform MSE quantile MSE improvement
2 0.0340 0.0261 23%
3 0.0085 0.0056 34%
4 0.00213 0.00176 17%

(measured on 200k standard-normal values clipped to $[-1,1]$, as blockwise absmax scaling produces). The 16 equal-probability levels are

$$\pm 1.000,\ \pm 0.708,\ \pm 0.542,\ \pm 0.417,\ \pm 0.311,\ \pm 0.216,\ \pm 0.127,\ \pm 0.042$$

with a gap at zero of $\pm0.042$ — the cost of using an even number of levels on a symmetric distribution, and the reason some implementations add an exact zero.

Implementation from scratch

```python import numpy as np class LoRALinear: """y = x W0^T + (alpha/r) * (x A^T) B^T, with W0 frozen.""" def __init__(self, d_in, d_out, r=4, alpha=8.0, seed=0): rng = np.random.default_rng(seed) self.W0 = rng.normal(0, 0.5, (d_out, d_in)) # frozen pretrained weight self.A = rng.normal(0, 1 / np.sqrt(d_in), (r, d_in)) # down-projection self.B = np.zeros((d_out, r)) # up-projection, zero init self.scale = alpha / r self.x = None self.ax = None def forward(self, x): self.x = x self.ax = self.A @ x # (r, batch) return self.W0 @ x + self.scale * (self.B @ self.ax) def backward(self, grad_out): """Return (dL/dA, dL/dB) given dL/dy. W0 has no gradient: it is frozen.""" s = self.scale self.dB = s * grad_out @ self.ax.T # (d_out, r) self.dA = s * (self.B.T @ grad_out) @ self.x.T # (r, d_in) return self.dA, self.dB def n_trainable(self): return self.A.size + self.B.size if __name__ == "__main__": d_in, d_out, r = 6, 5, 2 layer = LoRALinear(d_in, d_out, r=r, alpha=4.0, seed=1) rng = np.random.default_rng(7) x = rng.normal(size=(d_in, 1)) g = rng.normal(size=(d_out, 1)) # upstream gradient dL/dy y = layer.forward(x) dA, dB = layer.backward(g) print("dA at init (all zeros by construction):\n", np.round(dA, 8)) print("dB:\n", np.round(dB, 6)) # finite-difference check of dB after one step has moved B layer.B = 0.1 * rng.normal(size=(d_out, r)) dA, dB = layer.backward(g) eps, num = 1e-6, np.zeros_like(layer.B) for i in range(d_out): for j in range(r): orig = layer.B[i, j] layer.B[i, j] = orig + eps lp = float((g * layer.forward(x)).sum()) layer.B[i, j] = orig - eps lm = float((g * layer.forward(x)).sum()) layer.B[i, j] = orig num[i, j] = (lp - lm) / (2 * eps) print("max |analytic - numeric| for dB:", np.abs(dB - num).max()) print("trainable params:", layer.n_trainable(), "vs full:", d_in * d_out) ```

What to expect. dA is a matrix of exact zeros, because $\mathbf{B}=\mathbf{0}$ makes the first step's gradient with respect to $\mathbf{A}$ vanish — this is the zero-init working, not a bug. After perturbing $\mathbf{B}$, the analytic and finite-difference gradients of dB agree to about $10^{-10}$, and the last line prints 22 trainable parameters against 30 for the full matrix.

Worked example

The model. 32 layers, $d=4096$, $d_{ff}=11008$, $V=32000$, untied embeddings. Parameters: $32(4d^{2}+3dd_{ff}) + 2Vd = 32(67.1\text{M} + 135.3\text{M}) + 262\text{M} = 6.738$B.

Full fine-tuning memory. $6.738\times10^{9}\times16$ bytes $= 107.8$ GB $= 100.4$ GiB — before activations, which scale with batch and sequence length and typically add tens of GB. Minimum three 80 GB devices; realistically four to eight.

LoRA memory. Frozen base at bf16: $6.738\times10^{9}\times2 = 13.48$ GB $\approx 13.0$ GiB, which is the dominant term if you keep the base resident in bf16. Adapters: 39.98M trainable at 16 bytes each $= 0.64$ GB. Optimizer state is now 0.64 GB instead of 107.8 GB. Total 14.1 GB plus activations — one 24 GB card with small batches, one 80 GB card comfortably.

QLoRA memory. Base at 4.127 bits: $6.738\times10^{9}\times4.127/8 = 3.48$ GB $= 3.36$ GiB. Adapters 0.64 GB. Total 4.1 GB plus activations — a 24 GB card with room to spare, and this is the configuration that made 65B fine-tuning possible on a single 48 GB device.

LoRA parameter counts by rank, for all seven linear projections of every layer:

$r$ trainable share of 6.738B attention-only share of base
4 9.99M 0.148% 4.19M 0.062%
8 19.99M 0.297% 8.39M 0.124%
16 39.98M 0.593% 16.78M 0.249%
64 159.9M 2.373% 67.11M 0.996%

The 1,000-example arithmetic. 1,000 examples averaging 400 tokens: 400,000 tokens. At $6PD = 6\cdot6.738\times10^{9}\cdot4\times10^{5} = 1.62\times10^{16}$ FLOPs — about 11 GPU-seconds at 40% of peak, or 90 GPU-seconds if you spend most of the time on padding and data loading, which you will. This is why SFT quality is limited by data curation and not by compute, and why running five data ablations is affordable and running one architecture ablation usually is not.

Merging. After training, $\mathbf{W} = \mathbf{W}_0 + \frac{\alpha}{r}\mathbf{BA}$ folds into a single $d_{\text{out}}\times d_{\text{in}}$ matrix. Inference latency is unchanged and the extra adapter file disappears. The merge is exact only in fp32 or where the sum does not lose precision — merging in bf16 introduces a rounding error of about $2^{-8}$ relative on the merged weight, which is usually acceptable and occasionally not. Merge in fp32 and cast afterwards.

Common misconceptions

"LoRA reduces training compute"

It reduces memory and the number of trainable parameters. The forward and backward passes still traverse every frozen weight, so the FLOP count is essentially unchanged. What you save is the 12 bytes per parameter of optimizer and gradient state, which is what actually prevents you from fitting a 70B model. Thinking LoRA makes training fast is a planning error of an order of magnitude.

"You should fine-tune on all tokens so the model sees the whole example"

Training on prompt tokens optimizes $\log p(q)$, not just $\log p(r\mid q)$, so it spends gradient on making the model better at writing the prompts — and with templated system preambles it spends most of it there. Mask the prompt. The only defensible exception is deliberately training on a document-completion objective, which is a different task.

"A small loss on the training set means the fine-tune worked"

With 1,000 examples and three epochs, training loss always falls to near zero. That is memorization. The signal is held-out loss and format adherence on unseen prompts, plus capability retention on the pretraining benchmarks. Any fine-tune reported without those three numbers has not been evaluated.

"Alpha and r are both hyperparameters to tune"

They appear in the forward pass only as the ratio $\alpha/r$, so they are one hyperparameter plus a convention. But the derivation shows the first step scales as $\alpha^{2}/r$ and the effective weight decay as $\lambda(r/\alpha)^{2}$, so $r$ also changes the dynamics at fixed $\alpha/r$ — the two are not interchangeable. $\alpha = r$ is the convention that keeps weight decay rank-invariant; it does not keep the step size rank-invariant, so a large change in $r$ still needs a learning-rate check.

"QLoRA degrades the model because 4 bits is lossy"

The base is frozen, so quantization error in it is a fixed perturbation of the input distribution, and the adapters train against that perturbation — they learn to compensate for it. Reported QLoRA results match 16-bit LoRA closely on standard benchmarks. Where 4-bit does hurt is the adapters themselves if you also quantize them, which QLoRA does not: they stay in bf16.

"The model learned the behaviour because the outputs look right"

Outputs look right on inputs that resemble the training distribution. Format adherence measured on 500 deliberately awkward prompts — unusual capitalisation, a trailing code block, a very long instruction, a conflicting system message — is the measurement that separates a learned behaviour from a learned style. This is cheap to run and almost always skipped.

Exercises

Warm-up (check understanding)

1. A 6.738B model is fine-tuned full-parameter. How many bytes of optimizer and master-weight state, and what is that in GiB?

2. A chat example is 900 tokens: 780 of template and prompt, 120 of response. By what factor does masking change the magnitude of the average per-token gradient?

3. If $\alpha = 16$ and $r = 8$, what is the scale factor, and what would you set $\alpha$ to for $r = 64$ under the $\alpha = r$ convention?

Solution 1. $16 - 2 - 2 = 12$ bytes per parameter of optimizer state, gradient and master weight; $6.738\times10^{9}\times12 = 80.9$ GB $= 75.3$ GiB. The two bf16 tensors add 25.1 GiB, for 100.4 GiB total. 2. Dividing by 120 instead of 900 multiplies the average term by 7.5, but more importantly it removes the 780 prompt terms entirely — which is not an 7.5x scaling of the same gradient, it is a different gradient. The prompt terms are 87% of the unmasked sum. 3. Scale factor $= 2$; for $r = 64$ set $\alpha = 64$ (scale 1). Under the convention, the scale factor is always 1.

Core (do the math)

4. Verify Eckart–Young on a concrete $2\times2$ matrix: $\mathbf{M} = \begin{pmatrix} 3 & 0 \\ 0 & 1 \end{pmatrix}$. What is the best rank-1 approximation, and what is the Frobenius error?

Solution $\mathbf{M}$ is already diagonal with singular values 3 and 1. The best rank-1 approximation keeps $\sigma_1 = 3$: $\mathbf{M}_1 = \begin{pmatrix}3&0\\0&0\end{pmatrix}$. The error is $\sqrt{\sigma_2^{2}} = 1$. Check against the formula: $\|\mathbf{M}\|_F = \sqrt{9+1} = \sqrt{10}$, $\|\mathbf{M}_1\|_F = 3$, and $\sqrt{10-9} = 1$. If instead $\Delta\mathbf{W}$ had spectrum $(3, 0.9, 0.05, 0.02)$, the rank-1 error would be $\sqrt{0.81+0.0025+0.0004} = 0.901$ — 90% of the energy is in the first direction, which is what "low-rank update" means quantitatively.

5. A LoRA adapter with $r=32$ is applied to $\mathbf{W}_0$ of shape $4096\times4096$. Compute the compression ratio, and compute the ratio if it is applied only to a $4096\times1024$ projection.

Solution Full: $4096\cdot4096 = 16{,}777{,}216$. Adapter: $32(4096+4096) = 262{,}144$. Ratio $= 262144/16777216 = 1.5625\%$, a 64x compression. For a $d_{\text{out}}\times d_{\text{in}} = 1024\times4096$ projection: full $4{,}194{,}304$; adapter $32(1024+4096) = 163{,}840$; ratio $3.906\%$. The compression is worse for skinny matrices, which is why adapting down-projections costs relatively more than adapting square ones.

6. Derive the QLoRA storage for a 13B model with block size 64 and double quantization, and compare to bf16 and to 8-bit.

Solution At 4.127 bits: $13\times10^{9}\cdot4.127/8 = 6.71$ GB $= 6.25$ GiB. bf16: $13\times10^{9}\cdot2 = 26$ GB $= 24.2$ GiB. 8-bit blockwise (8 + 32/64 = 8.5 bits): $13\times10^{9}\cdot8.5/8 = 13.8$ GB $= 12.9$ GiB. So QLoRA is 3.9x smaller than bf16 and 2.1x smaller than int8 — the difference between two 24 GB cards and one.

7. Show that with $\mathbf{B}=\mathbf{0}$ the LoRA branch is exactly the identity map on the pretrained function, and explain why $\mathbf{A}$ can therefore be initialized randomly without risk.

Solution $\mathbf{h} = \mathbf{W}_0\mathbf{x} + \frac{\alpha}{r}\mathbf{BA}\mathbf{x}$; with $\mathbf{B}=\mathbf{0}$ the second term is the zero vector for every $\mathbf{x}$, so $\mathbf{h} = \mathbf{W}_0\mathbf{x}$ exactly — bit-identical, not approximately. Since $\partial\mathcal{L}/\partial\mathbf{A} = \frac{\alpha}{r}\mathbf{B}^{\top}\mathbf{g}\mathbf{x}^{\top} = \mathbf{0}$ at that point, the initial random $\mathbf{A}$ receives no gradient on the first step and cannot destabilize anything; it only matters through the product after $\mathbf{B}$ becomes nonzero. The one thing the initial $\mathbf{A}$ sets is the *scale* of the first update, which is why its initialization variance appears in Derivation 2, Step 6.

Stretch (build or break it)

8. Implement prompt-masked loss and measure how much a fine-tune's capability retention improves when you drop the learning rate by 10x and mix in 10% pretraining data. Describe the experiment precisely enough that someone else could run it.

Solution Four arms, same data and seed: (a) lr $2\times10^{-4}$, 3 epochs; (b) lr $2\times10^{-5}$, 3 epochs; (c) lr $2\times10^{-4}$ with 10% replay from the pretraining corpus mixed into each batch; (d) lr $2\times10^{-5}$ with 10% replay. Measure on three held-out sets: target-format accuracy, a general reasoning benchmark, and a perplexity measurement on held-out pretraining text. Expect: (a) highest target accuracy, largest perplexity regression; (b) smallest regression, some target loss; (c) intermediate on both. Report the Pareto frontier rather than a single winner. The precision required: identical example order, identical evaluation prompts, and a *fixed* evaluation harness version, because a changed prompt template will move the numbers more than the intervention will.

9. A 4-bit quantized base is used for QLoRA. Argue whether the adapter can compensate for quantization error in a layer it does not adapt, and what that implies for which modules to adapt.

Solution It cannot: the adapter's output is added to a frozen path that is already perturbed, so error in an unadapted module propagates downstream and the only correction available is whatever the adapted modules can express. Since the perturbation $\mathbf{E}$ enters as $\mathbf{W}_0+\mathbf{E}$ and the adapter contributes rank-$r$ corrections, the composed map can only fix error projected onto the adapted subspace. Empirically this is why QLoRA works best when adapting *all* linear projections rather than attention only: broad coverage gives the adapters a chance to correct quantization error across the whole network. The practical guidance is to check that adapters are present in every module type whose output feeds a residual stream, and to verify that a 4-bit base with adapters recovers the 16-bit baseline on a small task before committing to a large run.

10. Design an evaluation that would detect "the model learned the format but not the task" in a single afternoon, given 200 held-out examples and no budget for human annotation.

Solution Three cheap probes. (i) **Label-shuffle control**: retrain on the same examples with responses shuffled across prompts. If held-out *format* adherence stays high while *content* accuracy drops to chance, the original model learned content; if both stay high, it learned format. (ii) **Format-only baseline**: a model trained on 200 examples of the format with dummy content. Compare its format score to the real model's; if they match, the real model contributed nothing but format. (iii) **Adversarial formatting**: re-render 200 held-out prompts with different surface forms (extra whitespace, reordered fields, a distractor sentence). Behaviour that survives is behaviour, behaviour that collapses is pattern-matching. All three need only inference on 200 examples and no annotation, and (i) needs one extra training run of the same size — which, for 1,000 examples, is 90 GPU-seconds.
