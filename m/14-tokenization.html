Tokenization

The fixed, lossy map between text and tensors, and what it silently breaks.

on this page

Why this module exists

A language model never sees text. It sees integer indices into an embedding table, and the map from bytes to those indices — the tokenizer — is fitted before a single gradient step, never updated, and frozen for the life of the model. Skip this module and you will misread everything downstream: you will compare perplexities across models where the numbers are not commensurable, treat "the model cannot count letters" as an emergent mystery instead of a bottleneck you can locate to the exact tensor, ship likelihood evaluations that are systematically wrong because of one leading space, and treat vocabulary size as a free hyperparameter when it trades embedding parameters against sequence length against attention cost in arithmetic you can do. Tokenization is the smallest component of an LLM and the one that leaks most often into results.

Prerequisites check

If two or more of these are shaky, revisit M03.

  1. How many bits distinguish 8 equally likely outcomes? 50,000?
  2. Why is $H(p,q) \ge H(p)$, with equality only at $q = p$?
  3. Convert a per-token probability of $0.002$ to nats and to bits.
  4. If you double an alphabet, does the number of symbols needed to encode a fixed message rise or fall?
Answers 1. $\log_2 8 = 3$ bits; $\log_2 50000 = 15.61$ bits. 2. $H(p,q) = H(p) + D_{\mathrm{KL}}(p\|q)$ and KL is non-negative, zero only at $q=p$. Cross-entropy is entropy plus the price of the wrong distribution. 3. $-\log 0.002 = 6.215$ nats $= 8.966$ bits. 4. Falls, because each symbol now carries more information — but the alphabet, and therefore the embedding table, grows. That tension is this whole module.

Learning objectives

  • Implement byte-pair encoding from scratch, with the merge table, weighted pair counts, and deterministic tie-breaking.
  • Trace BPE by hand for three merges on a five-word corpus and predict the winning pair at each step.
  • Contrast the merge criteria of BPE (frequency), WordPiece (likelihood ratio), and Unigram (EM marginal likelihood), and state what each optimizes.
  • Convert a per-token cross-entropy into a per-byte cross-entropy and explain why only the latter is comparable across tokenizers.
  • Compute the parameter, length, and FLOP consequences of a vocabulary change for a named model shape.
  • Explain mechanically why a model that never sees a letter cannot count letters, naming the exact point where the information is destroyed.
  • Diagnose a tokenizer with a six-point checklist, and name four tokenization-based attack classes with their mitigations.

Notation and conventions

Symbol Meaning

$V$ vocabulary; $\|V\|$ its size
$w$, $f(w)$ a word type and its corpus frequency

$t$ bytes per token, $t = B/N$
$\alpha$ elasticity, $\alpha = d\log t / d\log V$

"Byte" always means a UTF-8 byte: a Chinese character is usually 3, an emoji 4. And $t$ is a property of a tokenizer and a corpus, never of a tokenizer alone — quoting bytes per token without naming the corpus is meaningless.

Core concepts

Character, word, subword

(1) Intuition. You must post a letter using a fixed set of rubber stamps. With 26 letter stamps you can spell anything but you stamp constantly. With one stamp per English word you stamp rarely, need a warehouse of stamps, and cannot stamp a name you did not anticipate. Subword tokenization is the compromise a postal clerk would invent: stamps for frequent chunks (the, ing, tion), letter stamps for everything else.

(2) Formal definition. A tokenizer is a pair $E:\Sigma^{*}\to V^{N}$ and $D:V^{N}\to\Sigma^{*}$ over bytes $\Sigma$. Character-level: $V=\Sigma$, so $N=B$. Word-level: $V$ is a set of word forms, the encoder splits on whitespace. Subword: $V$ contains strings of intermediate length chosen by a data-driven procedure, and the encoder is an algorithm, not a lookup.

(3) Why it is built this way. Character sequences for English are 4–5x longer than subword sequences and attention is quadratic in length, so a character model pays 16–25x more for the attention term and spreads meaning over positions that individually carry almost nothing. Word-level models have an unbounded vocabulary and produce unknown tokens that destroy information outright. Subword bounds the vocabulary while guaranteeing every byte string is representable, because the base layer contains all 256 bytes.

(4) Worked micro-example. The corpus low x5, lower x2, newest x6, widest x3 is 16 words and $3\cdot5+5\cdot2+6\cdot6+6\cdot3 = 79$ bytes. A character model sees 79 positions, a word model 16 positions with a 4-entry vocabulary, and the subword model you build below sees 53 — 1.49 bytes per token. Production English tokenizers reach 4.

Byte-pair encoding

(1) Intuition. Start with every byte as its own token. Find the most frequent adjacent pair across the corpus, fuse it into a new token, repeat. Frequent chunks fuse early, rare chunks stay split.

(2) Formal definition. Represent each word as a symbol tuple. The pair count is

$$c(a,b) = \sum_{w} f(w)\,\#\{i : w_i = a,\ w_{i+1} = b\}$$

Merge $(a^*,b^*) = \arg\max_{a,b} c(a,b)$, append $a^*b^*$ to $V$, and rewrite every word left to right replacing non-overlapping occurrences. Encoding applies merges in rank order: repeatedly fuse the lowest-ranked adjacent pair present.

(3) Why it is built this way. Greedy merging is a cheap proxy for the true objective, "find the vocabulary minimizing the corpus description length". Greedy is not optimal — a different first merge can lead to a better vocabulary — but it is $O(kB)$ instead of combinatorial. The end-of-word marker is not cosmetic: without it the the inside then and the standalone the share a token, word boundaries become unrecoverable at decode time, and the model has no representation for where a word ends.

(4) Worked micro-example. Words ab x3, ax x2 over symbols $a,b,x$. Counts: $c(a,b)=3$, $c(a,x)=2$. Merge a+b; corpus becomes ab x3, ax x2; counts now only $c(a,x)=2$. Merge a+x; no pairs remain, so training stops with $V=\{a,b,x,ab,ax\}$.

WordPiece and the likelihood criterion

(1) Intuition. Frequency is crude: a pair can be frequent only because both halves are frequent, so merging it teaches nothing. WordPiece asks how much more often the two symbols appear together than independence predicts, and merges the biggest surprise.

(2) Formal definition. $\mathrm{score}(a,b) = c_{ab}/(c_a c_b)$, and the pair with the highest score wins. Equivalently, the highest pointwise mutual information up to constants. WordPiece marks continuations with ## so that in at a word start and ##in inside a word are distinct tokens.

(3) Why it is built this way. In a corpus where e and s are both frequent, es wins on raw count while qu — rarer but nearly always adjacent — wins on WordPiece. The criterion prefers cohesive pairs over merely common ones.

(4) Worked micro-example. With $c_a=100$, $c_b=80$, $c_{ab}=40$ and $c_x=c_y=5$, $c_{xy}=5$: scores are $40/(100\cdot80)=0.005$ and $5/(5\cdot5)=0.2$. WordPiece merges xy, eight times rarer, because x and y never appear apart. BPE would merge ab.

Unigram LM tokenization and EM pruning

(1) Intuition. Run BPE backwards: start with a large candidate vocabulary, give each token a probability, treat the tokenization of each word as a hidden variable, prune the least useful tokens, re-estimate, repeat.

(2) Formal definition. With $\sum_u p_u = 1$ and $\mathcal{S}(x)$ the set of segmentations of $x$ into vocabulary items,

$$P(x) = \sum_{(u_1,\ldots,u_m)\in \mathcal{S}(x)}\prod_{i=1}^{m} p_{u_i}, \qquad \ell = \sum_{x\in\mathcal{C}}\log P(x)$$

computed by dynamic programming in $O(|x|^2)$ per string. Encoding at inference uses the Viterbi segmentation $\arg\max_S \prod_{u\in S}p_u$ — the single most probable one, not the summed one.

(3) Why it is built this way. The summed likelihood gives a principled pruning criterion: delete the token whose removal costs least, $\Delta_u = \ell(V)-\ell(V\setminus\{u\})$. It also yields multiple valid segmentations, enabling subword regularization — sample a random segmentation during training so the model does not overfit one canonical split. BPE has exactly one segmentation and cannot do this.

(4) Worked micro-example. $V=\{a,b,ab\}$ on the string ab with all probabilities $1/3$: $P(\texttt{ab}) = p_{ab} + p_a p_b = 1/3+1/9 = 4/9$, and Viterbi picks ab since $1/3 > 1/9$. Train on a corpus containing only ab and EM drives $p_{ab}\to 1$, after which pruning deletes a and b — catastrophic for unseen words. That failure is why single-character tokens are protected from pruning.

The unigram objective is a cross-entropy over tokens. Drag probability mass and watch entropy, cross-entropy, and KL move; the corpus log-likelihood is the negative of the cross-entropy term.

SentencePiece, byte-level BPE, and the space trick

(1) Intuition. Most tokenizers assume text is already split on whitespace, which is false for Chinese, Japanese, Thai, and for anything where words are not space-delimited — and it loses information, since "a b" and "a b" collapse to the same word sequence.

(2) Formal definition. SentencePiece normalizes input (usually NFKC), replaces every space with the meta-symbol ▁ (U+2581), and runs BPE or unigram over the raw character stream; decoding maps ▁ back to a space. Byte-level BPE instead applies a fixed reversible bijection from the 256 byte values to 256 printable code points (byte 0x20 becomes Ġ, U+0120), runs BPE on those, and never needs an unknown token. It also does no normalization, so no byte is unreachable.

(3) Why it is built this way. The ▁ trick makes the tokenizer lossless and language-agnostic. Because the space is a token, "hello" and "hello " are different sequences — correct behaviour, and the source of a notorious evaluation bug. Because the input is a raw stream, no pre-tokenization regex decides what a word is, so the same code path handles English, Thai, and DNA.

(4) Worked micro-example. "an ant" under SentencePiece becomes ▁an▁ant, tokenizing as ['▁an','▁ant']. Under byte-level BPE the space is byte 0x20, which the byte-to-unicode map sends to Ġ, so the tokens read Ġan, Ġant. This is why token dumps are full of Ġ and ▁.

Vocabulary size, length, and compression

(1) Intuition. A larger vocabulary means fewer tokens per sentence: shorter sequences, cheaper attention, more text per context window — but a larger embedding table, a larger softmax, and a long tail of rare tokens that barely trains.

(2) Formal definition. With untied input and output matrices the parameter cost is $2Vd$. For a fixed byte budget $B$ the token count is $N = B/t(V)$, and the training cost is

$$C(V) = 6P_{\mathrm{body}}N + 2Vd\,N + 12lLd\,N, \qquad N = \frac{B}{t(V)}$$

with $P_{\mathrm{body}} \approx 12ld^{2}$. The middle term is the output projection, which every token must multiply against.

(3) Why it is built this way. Every doubling of $V$ doubles the embedding table and shrinks the sequence only slightly, so the choice is a genuine optimum rather than a preference. The next section derives it.

(4) Worked micro-example. For $d=4096$, $l=32$: $P_{\mathrm{body}} = 12\cdot32\cdot4096^2 = 6.44$B. At $V=50{,}257$, embeddings cost $2\cdot50257\cdot4096 = 412$M, or 6.4% of the body; at $V=128{,}256$ they cost 1.05B, but if $t$ rises from 4.0 to 4.3 the token count for the same corpus falls 7%. Which wins depends entirely on the elasticity $\alpha$.

Tokens per byte, effective context, cost

(1) Intuition. Everything you thought was measured in text is really measured in tokens, and the conversion factor is not 1.

(2) Formal definition. Define fertility as tokens per byte $1/t$ and compression as $t$ bytes per token. A context of $L$ tokens holds $L\cdot t$ bytes — about $0.75L$ English words at $t=4$. Per-token cross-entropy $H_{\text{tok}}$ becomes $H_{\text{byte}} = H_{\text{tok}}/t$, and

$$\mathrm{PP}_{\text{byte}} = \exp(H_{\text{tok}}/t) = \mathrm{PP}_{\text{tok}}^{1/t}$$

(3) Why it is built this way. Billing and context are per token; quality is per byte. The exponent $1/t$ is why a small change in compression changes the per-byte number by a power, and why per-token perplexity leaderboards across tokenizers compare nothing.

(4) Worked micro-example. Model A: $\mathrm{PP}_{\text{tok}}=10$, $t=3.0$. Model B: $\mathrm{PP}_{\text{tok}}=10$, $t=5.0$. Then $\mathrm{PP}_{\text{byte}}^{(A)} = 10^{1/3} = 2.154$ and $\mathrm{PP}_{\text{byte}}^{(B)} = 10^{1/5} = 1.585$. B is 36% better per byte with an identical per-token number, and processes the same document for 60% of the bill.

Pathologies and diagnosis

(1) Intuition. The tokenizer is a fixed function with sharp edges, and every edge is a way for the model to misbehave in a way its weights cannot explain.

(2) Formal definition — five families, with mechanisms. Glitch tokens: a token whose embedding saw almost no gradient, usually because it came from junk (repeated markup, mojibake, spam) in the pretraining crawl. Its vector stays near its random initialization, so conditioning on it pushes activations off the training manifold; the model derails only when that exact token appears. Non-canonical encodings: é as U+00E9 versus e+U+0301, non-breaking spaces, zero-width joiners — visually identical, byte-different, tokenized differently, and therefore different inputs to the model, your filter, and your benchmark. Attacks: filter evasion via homoglyphs or zero-width characters; token smuggling, where a concatenation produces tokens never present in the filtered form; special-token injection, where a literal <|im_end|> in user text ends the turn; and fertility denial-of-service, where crafted input expands 5–10x in token count. Character-level tasks: there is no letter pathway (see the misconceptions). Lock-in: the tokenizer cannot be changed after pretraining without renumbering every index the model learned.

(3) Why it is built this way. None of these is an implementation bug; each follows from a fixed, frozen, string-to-index map trained on a non-uniform byte distribution.

(4) Worked micro-example. You evaluate Thai and see $\mathrm{PP}_{\text{tok}} = 8$ at $t = 1.2$, so $\mathrm{PP}_{\text{byte}} = 8^{1/1.2} = 5.66$. An English model with $\mathrm{PP}_{\text{tok}} = 20$ at $t=4$ has $\mathrm{PP}_{\text{byte}} = 2.11$. The Thai model is worse per byte despite the prettier per-token number. That inversion is the single most useful reason to compute per-byte metrics.

Diagnostic checklist. (1) Round-trip: assert decode(encode(s)) == s on real data. (2) Fertility per language and per content type; above 2.0 tokens/byte means the tokenizer is burning context on that slice. (3) Boundary probe: encode "x", " x", "x ", "x\n" and confirm the differences. (4) Glitch scan: tokens with near-zero corpus frequency whose embedding norm is anomalous. (5) Canonicalization: diff the tokenization of NFC and NFD forms. (6) Coverage: count single-byte fallback tokens on 1,000 domain documents.

The algorithm, step by step

  1. Pre-tokenize into word types with counts $\{(w,f(w))\}$, appending a boundary marker. For byte-level BPE, first map each byte through the reversible byte-to-unicode table.
  2. Initialize $V$ with every distinct symbol appearing anywhere.
  3. Compute $c(a,b)$ for all adjacent pairs, weighting each occurrence by the frequency of the word containing it.
  4. Select the maximum-count pair. Break ties with a fixed rule — smallest concatenation is reproducible.
  5. Record the pair with rank $k$ in the merge list, append the fused symbol to $V$, increment $k$.
  6. Rewrite every word left to right, replacing non-overlapping occurrences. Recompute pair counts from the rewritten corpus.
  7. Repeat from step 3 until $|V|$ hits the target or no pair clears a frequency floor.

Encoding a new string: split into words, append the marker, then repeatedly fuse the lowest-ranked adjacent pair present until no pair in the sequence appears in the merge table.

```text function TRAIN_BPE(corpus_counts, vocab_size, marker): words <- {(w + marker): f for (w, f) in corpus_counts} V <- sorted set of all symbols merges <- empty list while |V| < vocab_size: counts <- empty map for (word, f) in words: for i in 0 .. len(word)-2: counts[(word[i], word[i+1])] += f if counts is empty: break best <- max-count pair, ties broken by smallest concatenation merges.append(best) V.add(best[0] + best[1]) words <- rewrite each word, replacing best left to right function ENCODE(word, merges): sym <- characters of (word + marker) while len(sym) > 1: cand <- [(rank(sym[i], sym[i+1]), i) for i in 0 .. len(sym)-2 if (sym[i], sym[i+1]) in merges] if cand is empty: break i <- argmin of rank in cand sym <- sym[0:i] + [sym[i] + sym[i+1]] + sym[i+2:] return sym ```

Complexity. One merge step scans the corpus once, $O(B)$ time in bytes. Training for $k$ merges is $O(kB)$ time and $O(|V|)$ space for the merge table. Encoding a string of length $m$ is $O(m^2)$ with the naive rank-minimum loop and $O(m\log m)$ with a priority queue; production code pre-tokenizes on whitespace to cap $m$ and caches merges per word type.

Derivations

Derivation 1: per-token and per-byte cross-entropy differ by a power

A document of $B$ bytes becomes $N$ tokens, $t=B/N$. The mean per-token negative log-likelihood is

$$H_{\text{tok}} = -\frac{1}{N}\sum_{i=1}^{N}\log \pi(s_i \mid s_{

The document's total log-likelihood is the same number either way, so per byte it is that total divided by $B$:

$$H_{\text{byte}} = -\frac{1}{B}\sum_{i=1}^{N}\log\pi(s_i\mid s_{

Exponentiating, using $\mathrm{PP}=\exp H$:

$$\mathrm{PP}_{\text{byte}} = \exp\left(\frac{H_{\text{tok}}}{t}\right) = \left(\exp H_{\text{tok}}\right)^{1/t} = \mathrm{PP}_{\text{tok}}^{1/t}$$

The exponent $1/t$ is the whole story: equal per-token perplexities become per-byte perplexities separated by a power, and a model with worse per-token perplexity can be better per byte. Cross-tokenizer comparison must be done per byte or per character, never per token.

Derivation 2: the vocabulary optimum, and why it is not a clean number

Step 1 — cost per byte. Divide the cost model by $B$ and substitute $N = B/t$:

$$\frac{C}{B} = \frac{6P_{\mathrm{body}} + 2Vd + 12lLd}{t(V)}$$

Step 2 — differentiate. Keep the two leading terms, writing $u(V)=6P_{\mathrm{body}}+2Vd$. With $u'=2d$ and $t'=\alpha t/V$:

$$\frac{d}{dV}\frac{u}{t} = \frac{u't - ut'}{t^{2}} = 0 \implies u't = ut' \implies 2dt = u\frac{\alpha t}{V}$$

$$2dV = \alpha\left(6P_{\mathrm{body}}+2Vd\right) \implies 2dV(1-\alpha) = 6\alpha P_{\mathrm{body}} \implies V^{*} = \frac{3\alpha P_{\mathrm{body}}}{(1-\alpha)d}$$

Substituting $P_{\mathrm{body}} = 12ld^{2}$:

$$V^{*} = \frac{36\,\alpha\,l\,d}{1-\alpha}$$

Step 3 — the elasticity is not constant. If $\alpha$ were constant, $V^{*}$ would grow linearly in $ld$ and reach millions for a large model, which nobody does. The resolution is that $t(V)$ saturates. With Zipf-distributed word types, $p_r \propto 1/r$ for rank $r$, and word length growing logarithmically in rank, $\ell_r = a + b\log r$, and $H_V \approx \log V$:

$$t(V) = \sum_{r=1}^{V}p_r\ell_r \approx \frac{1}{\log V}\sum_{r=1}^{V}\frac{a+b\log r}{r} \approx \frac{a\log V + \frac{b}{2}(\log V)^2}{\log V} = a + \frac{b}{2}\log V$$

so $t$ grows only logarithmically and

$$\alpha(V) = \frac{V}{t}\frac{dt}{dV} = \frac{b/2}{t(V)}$$

decays like $1/\log V$. Substituting back gives a fixed point, $V^{*} = 36ld\,\alpha(V^{*})/(1-\alpha(V^{*}))$, which must be solved by iteration.

Step 4 — solve it. Calibrate $t(50{,}000)=4.0$ bytes per token for English and $b/2 = 0.18$ bytes per unit of $\log V$ (so doubling from 50k to 100k buys about 0.12 more bytes per token, a 3% length reduction). For $l = 32$, $d = 4096$, and body parameters $P_{\mathrm{body}} = 12ld^{2} = 6.44$B:

Iteration $V$ $t(V)$ $\alpha$ $V^{*} = 36ld\alpha/(1-\alpha)$
0 50,000 4.000 0.0900 466,674
1 466,674 4.402 0.0818 420,255
2 420,255 4.383 0.0821 422,225
3 422,141 4.384 0.0821 422,141

The fixed point is $V^{*}\approx 422{,}000$ tokens for a 6.4B-parameter body. The same equation at $l=80$, $d=8192$ gives $V^{*}\approx 1.97$ million. Both are far beyond any deployed vocabulary, and that gap is the informative part: the cost-per-byte argument, taken alone, wants a much larger vocabulary than anyone uses. Three things push back, and only the third is decisive.

Tail starvation. The expected training occurrences of token $u$ is $Np_u$. A token appearing once in the corpus receives exactly one gradient step on its input embedding and one on its output row, so its embedding stays near initialization. Under a Zipf tail most of a large vocabulary sits in exactly this regime, which makes the marginal token not merely useless but a source of inference noise — the glitch-token mechanism.

Memory bandwidth. Decoding one token reads every weight once, and $2Vd$ of them are embeddings. Bytes read per byte generated is again $(2P_{\mathrm{body}}+2Vd)/t$, now bounded by HBM bandwidth rather than FLOPs, which pushes the optimum down for small models and leaves large ones unchanged.

The elasticity decays faster than the model says. Step 3 assumed word length grows like $a+b\log r$ with $p_r\propto1/r$ held for all ranks. Real corpora are not Zipf-1 in the tail: beyond the point where the vocabulary covers whole words, adding a token saves essentially nothing, so $\alpha$ collapses rather than decaying like $1/\log V$. The fixed point therefore moves sharply downward once $V$ exceeds the number of distinct word forms the corpus actually contains — which for English is on the order of $10^{5}$.

The honest summary: there is no clean closed form for $V$. The FLOP argument gives $V^{*}\propto \alpha ld/(1-\alpha)$ and, with a smooth elasticity, a fixed point in the hundreds of thousands for a mid-sized model. Deployed practice is 32k to 256k, and the difference is explained by tail statistics and the collapse of $\alpha$ once whole words are representable, not by the cost model. This is an actively fitted area, not settled theory, and any specific number should be treated as a fit to a particular corpus.

Derivation 3: the WordPiece score is a first-order likelihood gain

With total token count $n$ and counts $c_x$, the maximum-likelihood unigram fit is $\hat{p}_x = c_x/n$, and the maximized log-likelihood is $\ell = \sum_x c_x\log(c_x/n)$. Merge $(a,b)$ at all $m$ adjacent occurrences, giving counts $c_a-m$, $c_b-m$, $c_{ab}+m$ and total $n-m$. The change is

$$\Delta\ell = (c_a-m)\log\frac{c_a-m}{n-m} + (c_b-m)\log\frac{c_b-m}{n-m} + (c_{ab}+m)\log\frac{c_{ab}+m}{n-m} - \ell$$

Assume $m \ll c_a,c_b$ and that the pair has not been merged before, so $c_{ab}=0$. Then to first order in $m$:

$$\Delta\ell \approx -m\log\frac{c_a}{n} - m\log\frac{c_b}{n} + m\log\frac{m}{n} = m\log\frac{m/n}{(c_a/n)(c_b/n)} = m\log\frac{\hat{p}_{ab}}{\hat{p}_a\hat{p}_b}$$

Since $m$ is monotone in $c_{ab}$ and $n$ cancels, maximizing $\Delta\ell$ maximizes $c_{ab}/(c_a c_b)$ — exactly the WordPiece score. So WordPiece is BPE with a likelihood-ratio criterion, derived as the first-order gain of a unigram model.

Derivation 4: the EM that drives unigram pruning

Maximize $\ell(\{p_u\}) = \sum_x \log\sum_{S\in\mathcal{S}(x)}\prod_{u\in S}p_u$. Introduce the segmentation as a hidden variable and use Jensen's inequality: for any distribution $q$ over segmentations,

$$\log P(x) = \log\sum_S q(S)\frac{P(x,S)}{q(S)} \ge \sum_S q(S)\log\frac{P(x,S)}{q(S)}$$

with equality at $q(S)=P(S\mid x)$. E-step: set $q_x(S) = \prod_{u\in S}p_u/P(x)$, computable by a forward-backward pass over the segmentation lattice, and accumulate expected counts $\tilde{c}_u = \sum_x\sum_{S,\,u\in S}q_x(S)$. M-step: $p_u = \tilde{c}_u/\sum_{u'}\tilde{c}_{u'}$, the standard result that the categorical M-step is normalized expected counts. Iterate, then prune the tokens with the smallest exact loss $\ell(V)-\ell(V\setminus\{u\})$, never pruning single characters. Because each step is coordinate ascent on a lower bound, $\ell$ increases monotonically — pruning is the only operation that removes capacity.

Implementation from scratch

```python from collections import Counter class BPE: """Greedy byte-pair encoding over whitespace-delimited words.""" def __init__(self): self.merges = {} # (a, b) -> (rank, a + b) self.vocab = [] # token strings in creation order @staticmethod def _count_pairs(words): """Weighted count of every adjacent symbol pair over all word types.""" c = Counter() for w, f in words.items(): for i in range(len(w) - 1): c[(w[i], w[i + 1])] += f return c @staticmethod def _merge(word, pair, new): """Replace every non-overlapping occurrence, left to right.""" out, i = [], 0 while i < len(word): if i < len(word) - 1 and (word[i], word[i + 1]) == pair: out.append(new) i += 2 else: out.append(word[i]) i += 1 return tuple(out) def train(self, corpus, num_merges, marker="_"): words = {tuple(w + marker): f for w, f in corpus.items()} self.vocab = sorted({c for w in words for c in w}) for rank in range(num_merges): counts = self._count_pairs(words) if not counts: break top = max(counts.values()) pair = min(p for p, c in counts.items() if c == top) # deterministic tie-break new = pair[0] + pair[1] self.merges[pair] = (rank, new) self.vocab.append(new) words = {self._merge(w, pair, new): f for w, f in words.items()} yield rank + 1, pair, top, len(self.vocab), words def encode(self, text, marker="_"): """Apply learned merges, lowest rank first, to each whitespace-delimited word.""" out = [] for word in text.split(): sym = tuple(word + marker) while len(sym) > 1: cand = [(self.merges[(sym[i], sym[i + 1])][0], i) for i in range(len(sym) - 1) if (sym[i], sym[i + 1]) in self.merges] if not cand: break _, i = min(cand) sym = sym[:i] + (sym[i] + sym[i + 1],) + sym[i + 2:] out.extend(sym) return out CORPUS = {"the": 12, "then": 5, "them": 4, "her": 6, "and": 9, "ant": 2, "an": 7} bpe = BPE() for step, pair, count, vsize, words in bpe.train(CORPUS, 12): ntok = sum(len(w) * f for w, f in words.items()) print(f"step {step:2d} merge {pair[0]}+{pair[1]:4s} count {count:3d} " f"|V| {vsize:3d} tokens {ntok:4d}") print(bpe.encode("the ant then her and")) ```

What to expect. Twelve rows matching the table above, $|V|$ climbing 9 → 21 and the token count falling 182 → 53, then an encoding of a held-out phrase. Note that ant encodes as ['an', 't'], not ['ant']: the merge an+t was never learned because ant was too rare, so the encoder falls back. That is correct behaviour, and it is why production tokenizers see rare words as several tokens.

Worked example

Input. $\mathcal{C}=\{$the:12, then:5, them:4, her:6, and:9, ant:2, an:7$\}$: 45 word occurrences, 92 characters, and with one trailing space per word, $B = 92+45 = 137$ bytes.

Step 0. $|V_0| = 9$ (_, a, d, e, h, m, n, r, t), one token per byte, so $N_0 = 182$ and $t_0 = 137/182 = 0.75$.

Step 1. $c(h,e)=27$ is the maximum, so merge h+e. The corpus becomes $12\cdot3+5\cdot4+4\cdot4+6\cdot3+9\cdot4+2\cdot4+7\cdot3 = 155$ tokens. Carrying on gives the table above: 21 tokens in the vocabulary, 53 tokens in the corpus.

Final state. Vocabulary: _, a, d, e, h, m, n, r, t, he, the, an, the_, and, and_, an_, her, her_, n_, then_, m_.

Compression. $t = 137/53 = 2.58$ bytes/token, up from 0.75 — a 3.4x reduction in sequence length, checked by re-encoding the seven training words: $12+5+8+6+9+6+7 = 53$ tokens.

Metrics. Suppose a model on this tokenizer reports $H_{\text{tok}} = 1.6$ nats/token. Then $H_{\text{byte}} = 1.6/2.58 = 0.620$ nats/byte $= 0.895$ bits/byte, $\mathrm{PP}_{\text{tok}} = \exp(1.6) = 4.95$, and $\mathrm{PP}_{\text{byte}} = 4.95^{1/2.58} = 1.86$. The uniform-byte baseline is exactly 8 bits/byte, so this toy tokenizer removes 89% of the per-byte uncertainty before the model predicts anything.

Why 4.0 is unreachable here. With 21 tokens most words are still one or two tokens. Reaching 4.0 bytes/token needs tens of thousands of tokens so that whole-word and multi-word pieces exist — that is Derivation 2's $t \approx a + (b/2)\log V$, and 21 is far down the curve.

Common misconceptions

"A token is a word"

A token is a byte string of any length from one byte up, chosen by frequency. Most production tokens are sub-word fragments; a word splits into 1–4 tokens and a rare word into many. So "the model knows $N$ words" cannot be made true, and vocabulary size and word coverage are different quantities.

"Tokenization is reversible, so it loses nothing"

Byte-level BPE is reversible; most production tokenizers are not exactly so, because they normalize Unicode (NFKC), collapse whitespace, and drop or replace control characters. Two inputs that normalize alike are indistinguishable to the model, and two visually identical strings can be different inputs. Run a round-trip check on your own data instead of assuming.

"The tokenizer is trained jointly with the model"

It is fitted first, by BPE or unigram EM, then frozen; the loss never differentiates through it. That is why a bad tokenizer is unfixable afterwards, why a domain vocabulary cannot be added without retraining, and why glitch tokens persist. Tokenizer quality is a cheap, early data decision and one of the highest-leverage ones in a pretraining project.

"Bigger vocabulary is always better"

A larger vocabulary buys shorter sequences and cheaper attention, and costs embedding parameters, a bigger softmax, and a long tail of undertrained tokens. Derivation 2 shows the optimum is a function of width, depth, and the corpus's Zipf slope. Empirically quality is flat within a factor of two of the optimum, which is why vocabularies cluster rather than being carefully tuned.

"Perplexity is a property of the model"

It is a property of model and tokenizer and corpus. Two models with identical per-byte cross-entropy report per-token perplexities differing by the ratio of their $t$, which can be 30% or more. Convert to bits per byte first, always.

"The model can see letters if you just ask it to look"

There is no letter pathway. Token indices index an embedding table; strawberry is a small number of tokens (commonly something like straw+berry, exactly which depends on the vocabulary) and the embedding is one vector per token. Nothing downstream has access to the bytes that produced it, so "how many r's in strawberry" asks the model to recall the spelling and then compute on an object that was never represented. It can often succeed from memorized association — the failure is probabilistic, not absolute — and chain-of-thought helps a little by giving more forward passes to recall with, not by restoring the information. This is a tokenization problem in the precise sense that the loss happens at the input boundary.

"Byte-level tokenizers need no vocabulary"

They need a 256-symbol base vocabulary, one per byte, plus BPE merges on top. The no-unknown-token guarantee comes from the byte fallback, not from the absence of a vocabulary.

Exercises

Warm-up (check understanding)

1. A corpus of 1,000 bytes tokenizes to 250 tokens. What is $t$, and how does the sequence length compare to a byte-level model?

2. Model A: $\mathrm{PP}_{\text{tok}}=12$, $t=3.5$. Model B: $\mathrm{PP}_{\text{tok}}=9$, $t=2.8$. Which is better per byte?

3. Why is $c(h,e)=27$ in step 1 of the trace, rather than the number of distinct words containing he?

Solution 1. $t = 1000/250 = 4$ bytes/token. The byte-level model emits 1,000 positions, so the subword sequence is 4x shorter — and the attention term, quadratic in length, is 16x smaller. 2. $\mathrm{PP}_{\text{byte}}^{(A)} = 12^{1/3.5} = 2.037$; $\mathrm{PP}_{\text{byte}}^{(B)} = 9^{1/2.8} = 2.142$. A wins despite the worse per-token number, because it packs more bytes into each prediction. 3. Counts are weighted by word frequency: `the` contributes 12, `then` 5, `them` 4, `her` 6, totalling 27 occurrences of the pair across the 45 word occurrences — not 4 distinct types.

Core (do the math)

4. Run three BPE merges by hand on $\{$aa:3, ab:2$\}$ with marker _. Give the merge list, $|V|$ after each merge, and the token count at each stage.

Solution Words: `(a,a,_)`:3, `(a,b,_)`:2. $V_0=\{a,b,\_\}$, $|V_0|=3$, tokens $=3\cdot3+2\cdot3=15$. Counts: $(a,a)=3$, $(a,\_)=3$, $(a,b)=2$, $(b,\_)=2$ — a tie at 3, broken toward `aa` (smallest concatenation). Merge 1 `a`+`a`: words `(aa,_)`:3, `(a,b,_)`:2; $|V|=4$; tokens $=3\cdot2+2\cdot3=12$. Counts: $(aa,\_)=3$, $(a,b)=2$, $(b,\_)=2$; merge 2 `aa`+`_`; $|V|=5$; tokens $=3+6=9$. Counts: $(a,b)=2$, $(b,\_)=2$, tie broken toward `ab`; merge 3 `a`+`b`; $|V|=6$; tokens $=3+4=7$. Merge list: $[(a,a),(aa,\_),(a,b)]$.

5. With $l=32$, $d=4096$, $\alpha=0.05$, compute $V^{*}$ and the untied embedding parameter count there, as a share of $P_{\mathrm{body}}$.

Solution $V^{*} = 36\cdot0.05\cdot32\cdot4096/0.95 = 235{,}929.6/0.95 = 248{,}347$. Untied embeddings: $2\cdot248347\cdot4096 = 2.034$B, against $P_{\mathrm{body}} = 12\cdot32\cdot4096^2 = 6.442$B, so 31.6% of the body. Large enough that tying the input and output matrices would move the optimum — the derivation assumed untied.

6. Show that if two tokenizers have equal per-byte cross-entropy on one document, their per-token cross-entropies are in the ratio of their bytes per token.

Solution From Derivation 1, $H_{\text{tok}} = t\cdot H_{\text{byte}}$. With $H_{\text{byte}}$ equal, $H_{\text{tok}}^{(1)}/H_{\text{tok}}^{(2)} = t_1/t_2$: the tokenizer with twice the compression reports twice the per-token cross-entropy on an identical document. That is the algebraic statement of "per-token loss rewards compression, not knowledge".

7. A 128k-token window at $t=4.0$ versus $t=2.5$, with 5.5 bytes per English word: how many words fit in each, and what does the difference cost at 0.30 USD per million input tokens?

Solution $131072\cdot4.0 = 524{,}288$ bytes $\to 95{,}325$ words; $131072\cdot2.5 = 327{,}680 \to 59{,}578$ words. The better tokenizer fits 60% more text in the "same" window, 35,747 more words. The price is identical — 131,072 tokens costs 0.0393 USD either way — so effective cost per thousand words is 0.412 USD versus 0.660 USD.

Stretch (build or break it)

8. Replace the BPE selection rule with the WordPiece score and run both on the toy corpus. Where do they first differ, and why?

Solution Change the selection to maximize `counts[p] / (marginal[a] * marginal[b])`, where marginals sum all pair positions. On this corpus step 1 agrees: $(h,e)=27$ with $c_h=c_e=27$ scores $27/729=0.0370$, while $(t,h)=21$ with $c_t=21$, $c_h=27$ scores $21/567=0.0370$ — a near-tie frequency resolves one way and the ratio another. The criteria diverge exactly when a pair's halves are individually very frequent, which is what Derivation 3 predicts: frequency counts opportunities, the ratio normalizes them away.

9. Build a glitch-token detector from a vocabulary and a 1M-word corpus. What do you do with the flagged tokens?

Solution Tokenize the corpus, count occurrences per token ID, and flag IDs with zero frequency. The stronger version ranks by anomalous embedding norm together with zero corpus frequency. You cannot remove a token without renumbering every ID the model trained on, so the workable responses are: at inference, detect the token in user input and rewrite it to an equivalent canonical surface form; at tokenizer construction for a *new* model, drop such tokens before training; and if you control pretraining, add the source strings to a blocklist. There is no post-hoc fix for a deployed model beyond input rewriting.

10. A filter blocks the substring "bomb". Give three ways an attacker gets semantically equivalent input past it, exploiting tokenization and Unicode, with a mitigation for each.

Solution (i) *Homoglyphs*: Cyrillic `Ь` or full-width `ｂｏｍｂ`, byte-different but read as `bomb`. Mitigation: NFKC-normalize before filtering. (ii) *Zero-width separators*: insert U+200B between letters so the substring match fails while the model still reconstructs the meaning; mitigation: strip Unicode category Cf before both filtering and tokenizing. (iii) *Concatenation smuggling*: assemble the string from pieces so no user-visible part contains the pattern, then let a later template fill or tool call produce it inside the prompt; mitigation: escape and delimit all interpolated content and re-check the fully assembled prompt. Add a fourth: literal `<|im_end|>` in user text, mitigated by escaping special tokens so user input can never produce them.

  1. State the three tokenization levels and one concrete failure of each.

  5. What does ▁ do, and which problem does it solve that whitespace pre-tokenization cannot?
  6. Give the exact conversion from per-token to per-byte perplexity.
  7. Derive $V^{*}=36\alpha l d/(1-\alpha)$ from the cost-per-byte model.
  8. Explain in two sentences, with the mechanism, why a model cannot count the letters in a word.
  9. Name three tokenizer pathologies and the diagnostic that catches each.
Answers 1. Character: sequences 4–5x longer, attention cost up 16–25x, weak per-position signal. Word: unbounded vocabulary, unavoidable unknowns. Subword: the compromise, but it fragments rare or foreign text and destroys intra-token characters. 2. $c(a,b)=\sum_w f(w)\,\#\{i: w_i=a, w_{i+1}=b\}$. The weight makes counts corpus-wide rather than type-wide, so a pair inside a frequent word beats the same pair inside a rare one. 3. $c_{ab}/(c_a c_b)$, the pair's co-occurrence over independence. Derivation 3 shows it is the first-order gain in a unigram model's maximized log-likelihood from that merge. 4. The segmentation. The E-step computes the posterior over segmentations of every string, $q(S)\propto\prod_{u\in S}p_u$, by forward-backward over the lattice, and accumulates expected token counts. 5. `▁` replaces the space so the space becomes a token and word boundaries survive. Whitespace pre-tokenization destroys the with-space/without-space distinction and cannot handle languages that do not delimit words. 6. $\mathrm{PP}_{\text{byte}} = \mathrm{PP}_{\text{tok}}^{1/t}$ with $t$ the bytes per token on that corpus. 7. Cost per byte is $(6P_{\mathrm{body}}+2Vd)/t(V)$; set the derivative to zero, use $t'=\alpha t/V$, get $2dV=\alpha(6P_{\mathrm{body}}+2Vd)$, so $V(1-\alpha)=3\alpha P_{\mathrm{body}}/d$, and with $P_{\mathrm{body}}=12ld^2$, $V^{*}=36\alpha ld/(1-\alpha)$. 8. A token's embedding is one vector and nothing downstream can read the bytes that produced it, so a letter question requires recalling the spelling from parameters and then operating on an object never represented. Hence the failure is probabilistic — memorized associations often work — rather than a reasoning defect more compute would remove. 9. Glitch tokens → frequency-versus-embedding-norm scan. Non-canonical encodings → NFC/NFD diff and round-trip test. Fertility blowup → per-language bytes-per-token measurement. Boundary bugs → encode `"x"`, `" x"`, `"x "`. (Any three.)

Further reading

  • Sennrich, Haddow, Birch, "Neural Machine Translation of Rare Words with Subword Units" (2016). The paper that brought BPE into NLP; extract §3 for the merge algorithm and the end-of-word convention.
  • Gage, "A New Algorithm for Data Compression" (1994). BPE's origin as a compression scheme. Read it to see that it was never designed for language, which explains its indifference to morphology.
  • Wu et al., "Google's Neural Machine Translation System" (2016). Source of the WordPiece criterion and the ## continuation convention.
  • Kudo, "Subword Regularization" (2018). The unigram LM tokenizer, EM pruning, and multi-segmentation sampling; extract §3 for the pruning criterion.
  • Kudo and Richardson, "SentencePiece" (2018). The ▁ encoding, lossless detokenization, and the case against pre-tokenization.
  • Radford et al., "Language Models are Unsupervised Multitask Learners" (2019). GPT-2's byte-level BPE and the byte-to-unicode bijection; extract §2.
  • Karpathy, "Let's build the GPT Tokenizer" (2024, free video). A from-scratch implementation that reproduces the pathologies here, including the spelling failures.
  • Rust et al., "How Good Is Your Tokenizer?" (2021). Measures tokenizer quality against monolingual performance; extract the fertility numbers for non-English languages.
