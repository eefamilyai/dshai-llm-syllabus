Evaluation

A score without an interval and a contamination check is not a measurement.

on this page

Why this module exists

Everything else in this curriculum produces a number you could fool yourself with, and this module is about not doing that. A model gains two points on a benchmark; is that a better model, a luckier seed, a reformatted prompt, or a test set it was trained on? Those four have the same headline number and completely different consequences. Evaluation is under-taught because it is not a technique you can implement once — it is a discipline of construct validity, statistics, and adversarial suspicion applied every time. Teams routinely ship a regression believing it is an improvement, then blame the generator for a retrieval problem, because nobody measured the components separately. If you skip this, every other module's results become unfalsifiable for you.

Prerequisites check

  1. If a fair coin is flipped 500 times and lands heads 400 times, what is the standard error of the estimated probability?
  2. What is a Type I error, and what does a 95% confidence interval mean precisely?
  3. Why can a model score above 25% on a four-option multiple-choice test by chance?
  4. What does temperature do to a sampling distribution, and why does it matter for reproducibility?
  5. What is the difference between precision and recall of a retrieval system?
Answers 1. $\operatorname{se} = \sqrt{\hat{p}(1-\hat{p})/n} = \sqrt{0.8 \times 0.2/500} = 0.0179$. 2. Rejecting a true null hypothesis. A 95% interval is a procedure that covers the true value in 95% of repeated samples — not a 95% probability that this particular interval contains it. 3. Because option order and format can bias the model, and because several options may be plausible; a model that always answers "A" scores 25%. A meaningful baseline is the score of a model that sees only the options, not one that output nothing. 4. It rescales logits before sampling; at $\tau = 0$ decoding is deterministic, at high $\tau$ nearly uniform. Any evaluation not fixing or averaging over it is not reproducible. 5. Precision is the fraction of retrieved items that are relevant; recall is the fraction of relevant items retrieved. If 1 or 2 is shaky, revisit **M03**; the rest are in **M15**.

Learning objectives

  • State the four components of a benchmark and identify which one a claimed improvement probably changed.
  • Detect contamination empirically with n-gram overlap, perturbation, and rank-based tests, and explain what each can and cannot show.
  • Score a multiple-choice benchmark without the three standard length, order, and format biases.
  • Design an LLM-as-judge protocol that controls position and verbosity bias, and report agreement with humans using a chance-corrected statistic.
  • Compute a Wilson interval, the sample size needed for a given resolution, and a paired comparison on the same items.
  • Compute expected calibration error and explain why a calibrated model is required for abstention.
  • Read a benchmark table and name at least five things it does not tell you.

Core concepts

What a benchmark actually measures

Intuition. A benchmark is a ruler you built yourself. If you sand a millimetre off it, every future measurement inherits the error, and the error is invisible because you never measure anything but the ruler.

Formal definition. A benchmark is a four-tuple: a prompt template, an item set $\mathcal{D}$, a scoring function $s(x, y^{*}) \in [0,1]$, and an aggregation over items. The published score is the aggregate. The construct you care about — reasoning, factual recall, instruction following — is not in the tuple at all, which is why a score change is never self-interpreting.

Why it is built this way. Capability is latent and every proxy is corruptible: once a benchmark decides funding and rank, effort flows toward the proxy rather than the construct. The defence is not a better benchmark but a rotating portfolio — private held-out sets, refreshed items, and measures whose failure modes differ.

Worked micro-example. MMLU has 14,042 test items over 57 subjects, so one percentage point is 140 items. At the top of the leaderboard, where models sit near 88%, a 1-point gap is well inside sampling noise for any single run — a fact that never appears in the table.

Contamination

Intuition. Practising on the exam is not cheating if you never see the exam; it is cheating the moment the exam paper is in the practice pile, whether or not anyone intended it.

Formal definition. Contamination is overlap between $\mathcal{D}$ and the model's training corpus $\mathcal{C}$. It is not binary: a test item can appear verbatim, in paraphrase, in a translated form, or as a solution discussion that leaks the answer. The measurable quantities are the fraction of items with an $m$-gram in $\mathcal{C}$, the model's perplexity on items versus matched controls, and the score drop under a semantics-preserving perturbation.

Why it is built this way. Web-scale corpora inevitably scrape benchmark pages, GitHub repos containing test files, and forum threads quoting problems. Once users chat with a model about a benchmark item, the item can enter the next model's preference data. The result is that every public benchmark is contaminated to some degree and the only question is by how much — which means the meaningful comparison is between models evaluated under the same contamination, not between a model and its own past.

Worked micro-example. Take 200 GSM8K items and rewrite each number (replace 24 apples with 37 apples, keeping the structure). If accuracy falls from 78% to 61% on the rewritten set, the 17-point gap is direct evidence that a substantial part of the original score came from recognising the item rather than solving it. Neither number is "the" score; the pair is the measurement.

Detection methods, ordered by strength of evidence:

  • $m$-gram overlap. Flag an item if any 13-gram appears in the corpus. Cheap, and it catches verbatim leakage only — the GPT-3 paper used exactly this on its own benchmarks.
  • Rank-based tests. Compare the item's least-predictable token losses (the Min-K% tail) against non-benchmark text of the same domain; memorised text has unusually low loss where it should be high.
  • Perturbation. Rewrite numbers or names and re-measure. The only method that tests behavioural dependence rather than textual overlap.
  • Temporal. A step change at the training cutoff is contamination; a smooth curve is capability.
  • Guided elicitation. Ask the model to complete the item verbatim. Near-proof.

Scoring multiple choice without fooling yourself

Intuition. If you grade by asking "which letter did it like", you measure the model's taste in letters.

Formal definition. Three biases have to be removed. Length bias: scoring by the sum of log-probabilities of the option tokens penalises long options, because every extra token contributes another negative term, so compare $\frac{1}{|y|}\sum_j \log p(y_j \mid x)$ or normalise by the unconditional probability of $y$. Order bias: models prefer particular positions, so evaluate every permutation and average, or at minimum report one fixed rotation and its variance. Format bias: the model may score well by matching the surface pattern of the answer key, so report a label-only baseline — the model given only the options, no question — which should sit near chance and usually does not.

Why it is built this way. Multiple choice exists because it makes scoring cheap and unambiguous, not because it is a good instrument. Every fix costs compute: permutation averaging multiplies the item count by the number of options, which is why published numbers rarely do it and why published numbers from different harnesses disagree by several points on the same model.

Worked micro-example. A four-option item where the correct answer is a long sentence and the distractors are single words. Summing log-probabilities gives the short distractors a 5- to 10-token advantage, worth roughly 2 to 5 nats — enough to flip the argmax on items the model actually knows. Per-token averaging removes the advantage and typically moves a small model's score by 1 to 4 points; permutation averaging moves it by a similar amount again.

Generative evaluation, judges, and agreement

Intuition. Once answers are free text, someone has to grade them, and if that someone is a language model you have replaced a measurement with an opinion that has its own biases.

Formal definition. For free-form outputs the scorers are exact match, token-level $F_1$, execution against unit tests, and rubric grading. For code, pass@k is the probability that at least one of $k$ samples passes:

$$ \operatorname{pass@k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}, $$

where $n$ samples were drawn and $c$ passed. Note the plug-in $(1 - c/n)^{k}$ is a different and biased quantity, because samples are drawn without replacement.

Why it is built this way. Exact match is objective but brittle; a judge is flexible but biased. The known biases are position (first or last option preferred), verbosity, self-preference, and sycophancy toward a reference shown in the prompt. Each is systematic and does not average out, so the protocol must break the correlation: swap A and B and average, randomise order, state criteria explicitly, hide provenance, and calibrate against a few hundred human labels.

Worked micro-example. A judge agrees with humans on 85% of 200 items. Chance agreement, given both raters pass 80% and 75% respectively, is $p_e = 0.80 \times 0.75 + 0.20 \times 0.25 = 0.65$, so $\kappa = (0.85 - 0.65)/(1 - 0.65) = 0.57$ — respectable but far less impressive than 85%, and the gap is the whole argument for chance correction. For pairwise preference, the standard model is Bradley–Terry, $P(A \text{ beats } B) = \sigma(\theta_A - \theta_B)$, fitted by maximum likelihood; leaderboard "Elo" numbers are a monotone reparameterisation of the fitted $\theta$.

Confidence intervals, resolution, and paired designs

Intuition. Two models at 80% and 83% on five hundred questions are, statistically, the same model wearing different hats.

Formal definition. With $n$ independent items and observed accuracy $\hat{p}$, the Wilson score interval is

$$ \frac{\hat{p} + \frac{z^2}{2n} + \delta z\sqrt{\frac{\hat{p}(1-\hat{p})}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}} . $$

For two models evaluated on the same items, never compare their separate intervals. Use the discordant pairs: with $b$ items only A got right and $c$ only B, the difference is $\hat{p}_A - \hat{p}_B = (b-c)/n$ and its standard error is $\sqrt{b+c}/n$ — it depends only on the pairs where they disagree.

Why it is built this way. The interval answers "how much would this move on a rerun"; resolution answers "what differences can this set even see". Reporting neither invites the field's commonest error: treating a 2-point gain as real. Pairing is more powerful because agreement between models carries no information about which is better.

Worked micro-example. Resolution at $p = 0.5$: $n = 384$ gives $\pm 5.0$ points, $n = 2{,}401$ gives $\pm 2.0$, $n = 9{,}604$ gives $\pm 1.0$. Now the paired case: two models on $n = 500$ items, $b = 60$, $c = 75$. The difference is $-3.0$ points and the interval is $-7.6$ to $+1.6$ — it contains zero, so the "improvement" is not established. Suppose instead they agree on almost everything, $n = 1000$ with $b = 5$, $c = 15$: the paired standard error is $\sqrt{20}/1000 = 0.45$ points against an unpaired $1.34$ — three times the resolution for free, from reusing the same items.

Two more sources of variance deserve the same treatment. Seed variance: sample with several seeds and report mean and standard deviation, because greedy decoding is a single draw and can be an unlucky one. Prompt-format variance: the same items under two instruction phrasings routinely differ by several points, so a template is part of the benchmark, not a detail — version it, and test more than one.

Calibration

Intuition. A model that says "90% sure" and is right 60% of the time is not merely inaccurate; it is unusable for any decision that depends on knowing when to abstain.

Formal definition. A model is calibrated if, over all items where it reports confidence $q$, the accuracy is $q$. Bin the predictions by confidence, and

$$ \mathrm{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n}\,|\operatorname{acc}(B_m) - \operatorname{conf}(B_m)| . $$

The Brier score, $\frac{1}{n}\sum_i (\hat{q}_i - y_i)^2$, decomposes into a reliability term (the calibration error), a resolution term (how much the confidence varies, which is good), and an irreducible uncertainty term.

Why it is built this way. Thresholds for routing, escalation, and abstention are only meaningful if the number means something. Post-hoc temperature scaling — dividing logits by one fitted $T$ — often cuts ECE by 2 to 4 times without changing accuracy, because it alters only the sharpness of the distribution.

Worked micro-example. 100 items in three bands: 70 at 0.95 confidence with 63 correct, 20 at 0.75 with 12 correct, 10 at 0.45 with 3 correct gives $\mathrm{ECE} = 0.7(0.05) + 0.2(0.15) + 0.1(0.15) = 0.080$, an overconfidence of roughly the same size in every band — the signature a single temperature can repair.

Drag probability mass between the classes and watch entropy and KL move; a calibrated model is one whose reported distribution matches the observed frequency, so the entropy you see should match the entropy of its actual error rate.

Reading a benchmark table critically

Intuition. A table is a compressed argument, and like any compression it discards the parts that would have changed your mind.

Formal definition. The checklist, in the order that most often changes the conclusion:

  1. Which model? Base, instruct, chat, or a reasoning variant — they differ more than most published gains.
  2. Whose number? Self-reported scores use the team's own prompt and parser; third-party harness runs often sit several points lower for the same weights.
  3. How many shots, and what template? Few-shot count alone is worth multiple points.
  4. What is the interval? Without the item count you cannot compute one, and the gap may be noise.
  5. Sampling parameters? Greedy, temperature 0.7, or maj@8 — not comparable to pass@1.
  6. Is it saturated? Above roughly 90% there is little resolution left and differences are formatting artefacts.
  7. Is contamination addressed? A perturbation check is worth more than the number.
  8. What was held out? If the test set drove model selection, the score is a training-set score.

The algorithm, step by step

Building and running an evaluation you can defend.

  1. Name the construct. Write the one sentence the eval must support, e.g. "this model extracts line items from invoices more accurately than the incumbent". If you cannot write it, stop.
  2. Choose the item source. Prefer items from production traffic, sampled and labelled, over public benchmarks; they share the deployment distribution and are not contaminated.
  3. Split before you look. Partition into $\mathcal{D}_{\text{dev}}$ for prompt and threshold iteration and $\mathcal{D}_{\text{test}}$, which is touched once. Decide the split by hash of item id so it is reproducible.
  4. Fix the scoring function. Write it as code, with its normalisation rules explicit; a human-readable rubric that only a human can apply is not a scorer.
  5. Compute the required $n$. From the resolution you need: $n = z^2\hat{p}(1-\hat{p})/h^2$ for half-width $h$.
  6. Run the baseline first. Empty-context, label-only, and incumbent baselines. A result with no baseline is a number, not a result.
  7. Repeat under variation. Three seeds, two templates. Report mean and standard deviation for each, not one column.
  8. Compare paired. Run every model on the identical item set and use the discordant counts, never two independent intervals.
  9. Check the components separately. If the system is retrieval plus generation, report retrieval recall@$k$ and end-to-end accuracy; otherwise you cannot attribute a failure.
  10. Freeze and version. Store prompts, items, seeds, model snapshot ids, and scorer version with the result, so a future regression can be bisected.

```text for model in models: # same items, same template, same seeds for seed in (0, 1, 2): preds[model][seed] = generate(model, test_items, template, seed) score[model][seed] = scorer(preds[model][seed], gold) report(model) = mean_over_seeds ± std_over_seeds compare(A, B) = discordant_counts(A, B) -> paired CI + exact test gate: ship only if lower bound of paired CI > 0 and no component regressed ```

Complexity. Running $m$ models under $s$ seeds over $n$ items costs $m s n$ generations; the statistics are $O(n)$ and free by comparison, which is why there is no excuse for reporting a point estimate. Disk is $O(msn)$ if predictions are stored, and they must be, because every question you will want to ask later is a re-scoring question.

Derivations

1. The Wilson interval, by inverting the score test

The Wald interval $\hat{p} \pm z\sqrt{\hat{p}(1-\hat{p})/n}$ fails at the edges: at $k = 0$ it collapses to a zero-width interval and at $\hat{p} = 0.1$ with $n = 10$ it runs below zero. The score interval instead inverts the test statistic that uses the null variance, and starts from

$$ \frac{(\hat{p} - p)^2}{p(1-p)/n} \le z^2 . $$

Clearing the denominator and collecting powers of $p$:

$$ n(\hat{p}-p)^2 = z^2 p(1-p) \;\text{ gives }\; (n + z^2)p^2 - (2n\hat{p} + z^2)p + n\hat{p}^2 = 0 . $$

with $\delta = -1$ selecting the lower bound and $\delta = +1$ the upper. The quadratic formula gives

$$ p = \frac{2n\hat{p} + z^2 + \delta \sqrt{(2n\hat{p}+z^2)^2 - 4(n+z^2)n\hat{p}^2}}{2(n+z^2)} , $$

and the discriminant simplifies to $4z^2 n\hat{p}(1-\hat{p}) + z^4$. Hence

$$ p = \frac{2n\hat{p} + z^2 + \delta z\sqrt{4n\hat{p}(1-\hat{p}) + z^2}}{2(n+z^2)} , $$

and dividing numerator and denominator by $2n$ gives the standard form quoted above:

$$ p = \frac{\hat{p} + \frac{z^2}{2n} + \delta z\sqrt{\frac{\hat{p}(1-\hat{p})}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}} . $$

At $k=0, n=20$ this yields $[0, 0.161]$ rather than $[0,0]$: the honest statement is "at most 16%", and its width is the price of having observed no failures in twenty tries.

2. Why paired comparisons are more powerful

Let $d_i = A_i - B_i \in \{-1, 0, +1\}$ for item $i$, with $b$ items at $+1$, $c$ at $-1$, and the rest at zero. Then $\bar{d} = (b-c)/n$ and

$$ $$\begin{aligned} \mathbb{E}[d_i^2] &= \frac{b+c}{n}, \ \operatorname{Var}(d_i) &= \frac{b+c}{n} - \frac{(b-c)^2}{n^2}. \end{aligned}$$ $$

The standard error of the mean is $\sqrt{\operatorname{Var}(d_i)/n}$, so

$$ \operatorname{se}(\bar{d}) = \frac{1}{n}\sqrt{(b+c) - \frac{(b-c)^2}{n}} \approx \frac{\sqrt{b+c}}{n} $$

for small effects. Compare the unpaired alternative, which treats the two scores as independent, $\operatorname{se} = \sqrt{2\hat{p}(1-\hat{p})/n}$. At $n = 1000$ and $p \approx 0.9$ the unpaired value is $0.0134$ regardless of how similar the models are, while the paired value is $0.0100$ when $b+c = 100$ and $0.0045$ when $b+c = 20$. The lesson is exact: paired resolution is governed by the number of disagreements, so two models that agree on 98% of items can be separated with a few hundred items, while two models that disagree often need far more. Note also the honest caveat — if nearly every item is discordant, $\sqrt{b+c}/n$ can exceed the unpaired estimate, and pairing buys nothing.

3. Kappa as chance correction

Raw agreement overstates, because two raters can agree by both saying "pass". Writing the 2×2 table as $(a,b;c,d)$ for (both correct, A only, B only, both wrong), observed agreement is $p_o = (a+d)/n$. Under independence, the expected agreement from the marginals is

$$ p_e = \frac{a+b}{n}\cdot\frac{a+c}{n} + \frac{c+d}{n}\cdot\frac{b+d}{n} . $$

Kappa is the fraction of the available above-chance agreement that was achieved:

$$ \kappa = \frac{p_o - p_e}{1 - p_e} . $$

With $p_o = 0.85$ and $p_e = 0.65$, $\kappa = 0.20/0.35 = 0.57$. Because $p_e$ rises with the base rate, $\kappa$ is not comparable across tasks with very different pass rates — report $p_o$, $p_e$, and $\kappa$, and say which task the judge was calibrated on.

Implementation from scratch

The statistics an evaluation needs, with no dependencies beyond the standard library.

```python from math import comb, sqrt def wilson(k, n, z=1.96): """Score interval for a binomial proportion: stays inside [0,1] at the edges.""" p = k / n d = 1 + z * z / n centre = (p + z * z / (2 * n)) / d half = z * sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d return centre - half, centre + half def paired_ci(b, c, n, z=1.96): """CI for p_A - p_B from discordant counts b (A only) and c (B only).""" return ((b - c) / n - z * sqrt(b + c) / n, (b - c) / n + z * sqrt(b + c) / n) def mcnemar_exact(b, c): """Two-sided exact binomial test at p=0.5 over the discordant pairs.""" n, k = b + c, min(b, c) return min(1.0, 2 * sum(comb(n, i) for i in range(k + 1)) / 2 ** n) def kappa(a, b, c, d): """Cohen's kappa for the 2x2 agreement table [[a,b],[c,d]].""" n = a + b + c + d po = (a + d) / n pe = ((a + b) * (a + c) + (c + d) * (b + d)) / (n * n) return (po - pe) / (1 - pe) def pass_at_k(n, c, k): """Unbiased estimator of pass@k from n samples with c correct.""" return 1.0 if n - c < k else 1 - comb(n - c, k) / comb(n, k) def ece(conf, correct, bins=10): """Expected calibration error, equal-width confidence bins.""" tot, err = len(conf), 0.0 for i in range(bins): lo, hi = i / bins, (i + 1) / bins idx = [j for j in range(tot) if lo <= conf[j] < hi or (i == bins - 1 and conf[j] == 1.0)] if idx: acc = sum(correct[j] for j in idx) / len(idx) avg = sum(conf[j] for j in idx) / len(idx) err += len(idx) / tot * abs(acc - avg) return err # ---- two models on the same 500 items ------------------------------------- both, a_only, b_only, neither = 340, 60, 75, 25 N = both + a_only + b_only + neither for name, k in (("A", both + a_only), ("B", both + b_only)): lo, hi = wilson(k, N) print(f"{name}: {k}/{N} = {100*k/N:.1f}% 95% CI {100*lo:.1f}-{100*hi:.1f}%") lo, hi = paired_ci(a_only, b_only, N) print(f"paired diff {100*(a_only-b_only)/N:+.1f} pp CI {100*lo:+.1f}..{100*hi:+.1f}" f" p={mcnemar_exact(a_only, b_only):.3f}") print(f"kappa={kappa(150,10,20,20):.3f} pass@5={pass_at_k(200,40,5):.3f}") conf = [0.95]*70 + [0.75]*20 + [0.45]*10 ok = [1]*63 + [0]*7 + [1]*12 + [0]*8 + [1]*3 + [0]*7 print(f"ECE={ece(conf, ok):.3f}") ```

What to expect.

```text A: 400/500 = 80.0% 95% CI 76.3-83.3% B: 415/500 = 83.0% 95% CI 79.5-86.0% paired diff -3.0 pp CI -7.6..+1.6 p=0.228 kappa=0.483 pass@5=0.676 ECE=0.080 ```

The two intervals overlap heavily, and the paired interval — the correct one — contains zero at $p = 0.228$. On 500 items a three-point gap is not evidence. Note also that papered_ci uses only $b+c$, so it stays narrow when the models agree, and that kappa(150,10,20,20) returns 0.483, not the 85% raw agreement that would first suggest itself.

Worked example

A team claims a 3-point win on a 500-item suite and wants to ship.

Question Computation Result
Individual accuracies $400/500$, $415/500$ 80.0%, 83.0%
Naive separate intervals Wilson 76.3–83.3, 79.5–86.0
Do the intervals overlap? yes, heavily inconclusive
Discordant counts $b=60$, $c=75$ 135 disagreements
Paired difference $(60-75)/500$ $-3.0$ pp
Paired standard error $\sqrt{135}/500$ $2.3$ pp
Paired 95% interval $-3.0 \pm 1.96 \times 2.3$ $-7.6$ to $+1.6$
Exact McNemar two-sided binomial $p = 0.228$
Verdict interval contains 0 not established

Now ask the question the table cannot answer: how many items would be needed? If the true gap is 3 points and disagreement is roughly 27% of items, the paired standard error scales as $1/\sqrt{n}$, so reaching significance needs about $500 \times (3.0/2.3)^2 \approx 850$ items — meaningfully more than the team bought, and cheap compared with the cost of shipping a regression that later has to be found in production. At \$0.19 per million output tokens with 400-token answers, a 500-item run costs about 4 cents; the evaluation is never the expensive part, the decision is.

Common misconceptions

"Higher MMLU means a better model"

MMLU is 14,042 four-option items at a saturation point where leading models cluster within a few points — smaller than the spread caused by few-shot count, prompt template, and answer parsing. It measures a mixture of recall, format-following, and test-taking skill, and every public model trains on data that contains some of it. Use it as one instrument among several, and never as a single ranking.

"A two-point improvement is a real improvement"

For 500 items at 80%, the 95% half-width is 3.5 points, so a 2-point gain is inside a single run's noise. The correct statements are "we cannot distinguish these" and "we need $n$ items to resolve a gap of this size", and both require the item count, which is precisely what most tables omit.

"Contamination only happens if you deliberately train on the test set"

It happens by scraping, by GitHub, by users pasting questions into a chat that later becomes training data, and by synthetic data generated from a model that memorised the items. The remedy is not abstinence but measurement: perturbation and rank-based tests, plus a private set that has never been on the public internet.

"An LLM judge is unbiased enough if you use a strong model"

A strong judge has stronger biases, not weaker ones: self-preference, verbosity, and position bias are all present and systematic, so they do not average out over items. The protocol — swap positions, randomise, hide provenance, state the rubric, calibrate against human labels, report $\kappa$ — matters more than the judge's size.

"Human evaluation is the gold standard"

Human raters have their own noise, drift, and instructions. Inter-annotator agreement is often only moderate, which means treating a human label as ground truth caps your measurement's ceiling. The gold standard is a protocol: written rubric, multiple raters, reported agreement, and adjudication for disagreements.

Exercises

Warm-up (check understanding)

1. A model scores 45/50. Give the Wilson 95% interval and state what it would take to claim 90% accuracy with a $\pm 2$-point interval.

Solution $\hat{p} = 0.9$, $n = 50$: the interval is roughly 0.786 to 0.958, a half-width of about 8.6 points. For $\pm 2$ points at $p \approx 0.9$ you need $n = z^2\hat{p}(1-\hat{p})/h^2 = 3.84 \times 0.09/0.0004 \approx 864$ items. Fifty items cannot support a claim finer than about $\pm 9$ points.

3. Two judges agree on 90 of 100 items, and both pass 50% of items. What is kappa, and why is it much lower than 90%?

Solution $p_e = 0.5 \times 0.5 + 0.5 \times 0.5 = 0.5$, so $\kappa = (0.9-0.5)/(1-0.5) = 0.8$. If instead both passed 90% of items, $p_e = 0.82$ and $\kappa = 0.44$ — the same 90% agreement means far less when agreeing is easy.

Core (do the math)

4. Model A scores 88.0% and B 89.2% on 1000 items, with $b = 30$ and $c = 42$. Is B better? Give the paired interval and the exact test.

Solution $\hat{p}_A - \hat{p}_B = (30-42)/1000 = -1.2$ points. $\operatorname{se} = \sqrt{72}/1000 = 0.85$ points, so the 95% interval is $-1.2 \pm 1.66$, i.e. $-2.86$ to $+0.46$ — still containing zero. Exact McNemar on 30 versus 42 gives $p \approx 0.16$. Not established: you would need roughly $1000 \times (1.2/0.85)^2 \approx 2000$ items to resolve a gap this size at this discordance rate.

5. A 500-item suite reports 82%. How many items are needed to resolve a 1-point difference against a model at 81% using a paired design with about 15% discordance?

Solution With discordance rate $r$, $b + c \approx rn$, so $\operatorname{se} \approx \sqrt{rn}/n = \sqrt{r/n}$. For a 1-point gap to be significant at 95%, need $1.96\sqrt{0.15/n} < 0.01$, so $n > 3.84 \times 0.15/0.0001 = 5760$ items. This is why fine-grained leaderboard differences require suites far larger than the common ones, and why leaderboards lean on pairwise preference aggregation instead.

7. 200 samples of a code problem yield 40 passing. Give pass@1, pass@5, and pass@10, and explain the ordering.

Solution pass@1 $= 0.20$, pass@5 $= 0.676$, pass@10 $= 0.899$. The ordering is forced: pass@$k$ is non-decreasing in $k$ because it is a probability of at least one success among more draws. The practical reading is that the model can solve this problem but rarely on the first attempt, so `maj@k` would beat `pass@1` — a distinction the single number hides.

Stretch (build or break it)

8. Implement a contamination check: for 100 benchmark items, compute the longest common $n$-gram with a candidate corpus and flag any item with an overlap of 13 or more tokens. Then argue why a clean result does not prove the model is uncontaminated.

Hint Tokenise both, build a set of 13-grams from the corpus, and for each item check membership of consecutive 13-grams. A clean result only excludes *verbatim* overlap: paraphrase, translation, and solution discussion all leak the answer without sharing a 13-gram. That is why the perturbation test measures behaviour rather than text.

9. Build a two-model comparison harness where the models are identical except for a random 2% of items, and verify that your pipeline reports "no difference". Then make one model genuinely 3 points better, and find the smallest $n$ at which your pipeline detects it at 80% power.

Hint Generate predictions directly rather than calling a model: sample Bernoulli outcomes with the desired agreement structure. Sweep $n$ from 200 to 5000 and record the fraction of 200 simulated runs where the paired interval excludes zero — that fraction is your power. You should find power rises steeply once $\sqrt{b+c}/n$ falls below the true gap divided by 1.96, which is the practical form of the resolution calculation.

10. Design an evaluation for a retrieval-augmented assistant where you can attribute a failure to retrieval or to generation. State the two numbers you would report and what each rules out.

Solution Report **recall@$k$** of the retriever against gold passages, and **conditional accuracy given that the gold passage was retrieved**. High recall with low conditional accuracy localises the fault in the generator; low recall caps the end-to-end score no matter how good the generator is, and no amount of prompt engineering will fix it. The third number worth having is the **oracle score** with the gold passage inserted by hand: it is the ceiling the current retriever allows, and it converts an argument about blame into arithmetic.

Self-test

  1. Name the four components of a benchmark and say which one a "2-point improvement" most often changed.
  2. Give three empirical contamination tests and rank them by strength of evidence.
  3. Why is a label-only baseline necessary on a multiple-choice benchmark?
  4. State three LLM-judge biases and the protocol fix for each.
  5. Write the Wilson interval and say why it is preferred to Wald at the edges.
  6. On 500 items at 80%, what is the 95% half-width, and what does that imply about reporting two decimal places?
  7. Why does the paired standard error depend only on discordant pairs?
Answers 1. Prompt template, item set, scoring function, aggregation. A 2-point gain most often reflects a change in template or scoring normalisation, not in the model. 2. Perturbation (behavioural), guided verbatim elicitation (near-proof), rank/loss-based detection (statistical); then $m$-gram overlap, which only catches verbatim leakage. Temporal discontinuity is a fifth and often decisive. 3. To separate knowledge from format-following. A model given only the options should score near chance; if it scores well above it, the benchmark is measuring test-taking skill. 4. Position bias — swap and average; verbosity bias — rubric with explicit criteria and length-blind scoring; self-preference — hide provenance and use a different model family than any candidate. 5. The score interval from inverting the test with the null variance; it never produces bounds outside $[0,1]$ and gives a finite width at $k=0$ or $k=n$, where Wald collapses to zero width. 6. About $\pm 3.5$ points. Reporting two decimal places claims a resolution the item set cannot support; one decimal is already optimistic. 7. Because items where the two models agree contribute zero to the difference and therefore zero to its variance. Only disagreements carry information about which model is better. 8. Reliability (calibration error), resolution, and uncertainty. Resolution — how much the confidence varies across items — is good to have large; reliability is good when small.

Further reading

  • Hendrycks et al., "Measuring Massive Multitask Language Understanding" (ICLR 2021). The MMLU paper; read the item counts and subject breakdown, then notice how little of the construct validity argument is about the score itself.
  • Brown et al., "Language Models are Few-Shot Learners" (NeurIPS 2020), Appendix C. The origin of the 13-gram contamination heuristic and an unusually candid self-audit of a benchmark table.
  • Zheng et al., "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena" (NeurIPS 2023). Where position, verbosity, and self-enhancement bias are measured rather than asserted, plus the swap-and-average protocol.
  • Cohen, "A Coefficient of Agreement for Nominal Scales" (1960). The kappa paper. Short, and reading the original makes clear what the chance correction is correcting for.
  • Guo et al., "On Calibration of Modern Neural Networks" (ICML 2017). Reliability diagrams, ECE, and temperature scaling; the figures are the fastest way to see overconfidence appear as depth increases.
